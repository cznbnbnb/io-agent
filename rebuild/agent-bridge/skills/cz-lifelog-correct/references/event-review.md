# 先判归属，再校对原句

先读当天有效稿，圈出标题、开篇、结尾和带“你”的动作。对每一个可能成为当天主线的事件，写下这句话的答案：“陈峥当时具体做了什么，哪句原话能证明？”已被订正过的标题也要问。日记可以记录工作、生活或给助手的口述。

| 与本人的关系 | 怎样落笔 |
|---|---|
| 本人经办或亲历 `own` | 本人发出要求、交付文件、观察结果或直接描述经历。写明他实际做的那一步。 |
| 本人参与 `participated` | 有可信的插话、答复、承接任务或行动。只将这部分归给本人，例如“你问了复测条件”。主线若用这个事件，写本人参与的动作。 |
| 现场背景 `background` | 能确认是旁人主持、讨论或媒体播放，而本人在该事项上的实质动作缺乏依据。分段可以如实记录，日总结按需要留一句背景，或从日总结略去。保留逐字转写。 |
| 归属待核 `uncertain` | 对话对象、具体项目或本人角色还分不清。摘要收窄到能确认的事实，疑点记入台账并写明下一处核验位置。不得推断“本人完全没有参与”。 |

同一场会里，主持人的动作可能是背景，本人追问的一句话可以是参与。按需要拆成两个事件条目。群成员、被抄送、日历邀请、同型号、录音时长、`speaker=me` 和飞书零命中都只能提供线索。优先看本人发出的消息及对方回应、实际交付或测试反馈、带时间的直接口述。能辨认本人交代给助手的原句，也能证明他的注意力当时在另一件事上。只用能实际访问的材料。

## 找串场的实际次序

1. 从一个容易辨认的词往回找。比如在全日转写中搜“简易模”，读到上一句明确的对象、接通电话或换人处，再向后读到挂断或新会议开场。核对北京时间、交谈对象、项目/实物、批次和动作。
2. 展开相邻转写材料和飞书通话起止，核对同一时刻的私聊、群聊或文档。两份材料整体时间重叠时，使用具体发言的时间。若同一时刻可听到两组人说话，分别建条目，可使用重叠时间区间。
3. 对每个事件留下“时间、场景、对象、本人角色和支持原话”。混杂时再写明与哪段分开、凭什么分开。一次查出的证据供转写、分段标题、提纲和日总结共用。保留仍不确定的项目名或单位时，不能把它接到另一个已确认的项目上。
4. 回到每一个动词，区分提出、转达、要求验证、实际复测、部分改善、验收或关闭。不同机器、不同批次、不同观察时间分开记。判定连接错误时，要改清句间关系，只换一个名词常会留下原来的错误结论。
5. 逐句检查日总结标题、开篇和结尾。只要它们还把旁人的会当成本人的成果，就沿用原有语气把重心移到本人确实做过的事。当天没有足够依据定主线时，用如实的时间或生活叙述开篇。已证实的背景可以留在分段。遇到较大的局部调整，在本地记录对应的错归因。

## 三个复核样例

| 录音或文字线索 | 合理的写法 |
|---|---|
| 同事开场筛出约70项，录音中同时能辨认出本人在向助手交代日记订正 | “同事开始过尚未关闭的问题。你也交代了前几天的智记要怎么订正。”本人是否有个别技术插话要另核。可以把日总结开篇留给有本人直接行动的另一件事。 |
| 18:35 的镜头电话谈硅胶和简易模，18:48 另谈断流，19:03 门铃评审才开场 | 简易模归镜头验证，对焦孔加大1毫米归门铃评审。断流所属机型缺证时只写实际排查动作。两处都出现“模糊”不能串用因果。 |
| 同一款设备出现实时流马赛克和黑点，前者调整播放器，后者刷固件做同板对照 | 各记各的验证方法和结果。“换库后这一轮未复现”“刷固件后黑点变小”分别写回对应现象。 |

以上只演示判法。每天以当日可访问的原始证据重新确认，不把样例当成角色名单或替换词典。事件表格式和程序检查见 [CLI 与写回 §3](cli-and-writeback.md)。
