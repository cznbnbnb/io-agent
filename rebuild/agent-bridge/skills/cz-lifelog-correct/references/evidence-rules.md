# 证据与误判

## 什么足以修改

| 情况 | 做法 |
|---|---|
| 同一事件的完整消息、明确型号的 BOM/图纸、正式联系人信息或会议逐字稿直接支持候选；时间、对象一致，无反证 | 最小订正，证据注明对应 block 和支持的事实 |
| 相邻语句可以唯一解释同音误识别，外部资料确认该实体/术语及事件 | 可订正；保留原句结构，不能扩写事实 |
| 多条来源互相复制或转述同一段 AI 总结 | 不是多份独立证据，继续找原始材料 |
| 熟悉的名字、看似合理的术语、搜索命中很多 | 只形成候选，不足以写回 |
| 两种写法都出现，项目/批次不明，缺关键上下文 | 保留；列明分歧和待核来源 |
| 数字、数量、成交、日期、责任归属或否定词改变 | 必须有直接支持，不用音近猜测 |
| 聊天显示没有提到某事 | 不能据此认定这件事没发生 |

每条证据至少记录：渠道、消息时间/文档版本与适用日期、message_id 或文档 token + 段落/表格行、必要原文、支持哪个改动。不能用一句“综合多日资料”支持全部修改。

## 摘要里保留一句肯定话，需要什么证据

先把“人名、项目、数字出现过”拆成可判断的句子：**在什么事件里，谁对什么对象做了什么，当时结果怎样**。对摘要里的肯定句、标题和提纲，主动找支持这层关系的原话。没有反证或与同源 AI 总结一致，不算正面证据。下面是示意，不是任何特定日期的事实字典。

| 要核的关系 | 先查哪段原话 | 证据只能支持一半时怎么写 |
|---|---|---|
| 提出 / 转达 / 受派 / 实测 | 看原消息发送人、引用链、任务接受者以及有无测试反馈。“甲转发”只能证明甲提供了步骤，不保证甲是首创者；“让乙试一下”不能证明乙已测。 | 可写“甲给出参数，你请乙按这组参数验证”。没点名作者时写“讨论了这个办法”，不把群成员推为提出者。 |
| 同一事件 / 不同事件 | 对齐本地时间、通话起止、项目和实物、参与者。连录、同一时段或同一型号都不是充分条件；挂断、转场、另一会议开场要回看两端。 | 前一通谈镜头压合、简易模，下一场谈门铃开孔，就把两件事分开记。项目不能确定时只还原谈话，不猜它属于哪一款。 |
| 要求 / 承诺 / 执行 / 完成 | 看是请求、将来式、执行反馈还是结果/签收/验收。数量要分清是清单总数、已处理数还是已通过数；一条现场原话足以支持时，不要求双源。 | “筛出约70个未关闭项，开始逐项讨论”可写“围绕约70项展开评审”；没有结果记录，不能写“70项逐一过审”，也不能反写成“都没完成”。 |
| 规格、数值及单位 | 对照原话前后文、同事项图纸/SOP及适用版本；提纲和正文相互矛盾时两处都复查。 | 原始转写“三号”不猜成“3毫米”。若明确的是引脚太长、要求剪短，摘要写这两个事实；单位在本地待核，不留两个互相冲突的确定规格。 |

对外部资料查不到、原话也不清的，仅当有依据落到一个更窄的事实时才收窄；不因“没搜到”删除真实生活细节。不要把后来的决定当成当天已完成。文风见 [原文校对示例](style-guide.md)。

## 实战中容易误判的情形

- **“舞台”与“5 台”**：只有样机交接数量和前后话题都吻合时才能改。不能把全日所有“舞台”批量替换。
- **“蚌埠”与“BOM”**：同一时刻消息直接出现 BOM 物料确认时可订正；仅因工作场景像 BOM 不够。
- **型号相近**：CK023、CK021、其他项目必须分清；同群的数量、批次和配件不能互相借用。
- **人名**：以联系人或签名、参与者与同事件消息为依据。未知名字不因为“更熟悉另一人”而替换。昵称、恋人称呼、“妈妈”等单词不能推断亲子/婚姻关系。
- **发言与责任**：别人汇报订单、收款、税务、报价，不自动成为用户已完成工作；用户旁听也不等于与其无关。
- **视频与现实**：小说人物、直播顾客订单、手机评测、游戏台词、歌曲、登山视频可能混入智记。结合上下文识别播放内容，不直接删除所有 `others`，也不能仅凭离奇程度判定是媒体。
- **计划与结果**：“明天拿”“询价”“要申请”“讨论按 50%”不等于今天拿到、成交、批准、最终执行。新文档后来的修订不能倒灌成历史状态。
- **时间**：ISO `Z` 先转 +08:00，午后会议不能写成早上；开始结束覆盖两小时不证明某一事件持续两小时。
- **金额与数量**：报价、选项、试算、不同客户/批次、良品与不良品分别核实；不因为相邻出现就加总。
- **技术与医学闲聊**：订正谁说了什么，不把讨论、猜测或生活建议升级为已验证技术标准或医学事实。
- **图片/附件**：`[Image:...]`、文件名和标题不能代替读到图片/附件内容。关键证据在媒体里才获取并用目标环境的识图/文档工具读取；不可用就保留待核。

## 两类不同的保留

1. `verified_unchanged`：已核对，原文没有明确错误。可以复用版本相同的复核结论。
2. `unresolved`：已完成本轮可用查证，但依据仍不足。原话不猜改；摘要按上表保留可支持部分，剩下的问题及下一步来源记入待核；出现新的相关证据再核。不能将其当作“原文已证明正确”。

尚未阅读/尚未完成查询是 `pending`，不是 `unresolved`。摘要暂时无正文是失效状态，不是无内容。
