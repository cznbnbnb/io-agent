# 原文校对式订正

默认交付应让用户感觉“还是原来的那篇日记，错误被纠正了”。这里的示例说明编辑方式，不是对任意日期自动套用的事实。

## 从原句修，不从证据另写

原句：

> 今天最硬的一块骨头，是那张卡了好几天的极限盒线框图——最后你没有再等，把模型交给 AI。

假设证据只确认“极限盒”是“集线盒”的识别错误，其他叙述没有事实问题：

> 今天最硬的一块骨头，是那张卡了好几天的集线盒线框图——最后你没有再等，把模型交给 AI。

不要因此改写成“今天重点推进集线盒线框孔位图。经飞书与微信核实，该图已发送给相关人员”。后一句即使依据充足，也改变了原段落的叙述方式，并掺入核验视角。

原句已有明确数字、时间、参与者时，逐项核验并保留正确部分。若“几分钟”与证据不符，只修正这个时间表达，不连带改掉整段的节奏。

## 修正归属，保留生活叙事

原句：

> 傍晚到夜里，节奏松了下来。和孩子有了几句亲昵的来往，又让小艺在京东挑一款品牌正常、价格便宜、还能领券的抽纸。

若亲子关系没有依据，但闲聊和抽纸要求可核实，可局部改为：

> 傍晚到夜里，节奏松了下来。几句亲昵的闲聊之后，你又让小艺在京东挑一款品牌正常、价格便宜、还能领券的抽纸。

不要写成“零散的称呼不能推断成真实亲子互动，抽纸也未见下单结果”。这解释了编辑者为什么修改，却不再是在记当天的生活。

“让小艺挑选”本身没有声称已下单，就无需新增“未见下单结果”。同样，原句只写“谈价”，不要额外补一句“谈价不等于成交”。只有原文误写成已下单/已成交时，才把那个事实谓语改回选购/谈价，并保留其他正确细节。

## 改的是关系，不一定只是一个字

原句：“午后这个问题还在反复。你按小乙提出的办法把缓存调大，画面还是会卡。”消息是小甲贴出缓存设置，你随后让小乙去试。可改为：“午后这个问题还在反复。小甲给了缓存设置，你让小乙照着试，画面还是会卡。”最后一句关于画面的反馈也要有依据。保留原来开头和结果，只改中间的归属；不需要为凑字数把整篇改成项目纪要。

## 处理重复事件

若证据说明两段在讲同一次制图任务，保留原先时间顺序和不重复的细节，只改必要指代或删除重复成果。例如“后来再聊起这张图，你说连调试总共用了二十几分钟”。不能在正文写“现有记录不宜再算成另一个独立完成的任务”。去重理由写入 evidence。

## 事实问题不靠保留风格掩盖

- 错误项目、数量、已完成状态、人物关系和无依据的心理活动仍应纠正；不是要求机械保留每句话。
- 有依据的感受与原有日记口吻可以保留。不能一概把带温度的表达删成项目报告，也不能为补偿删除而另造情绪。
- 有些事实在当时确实未定，可以自然写“还在确认”“等下周一的结论”；这是当天事件的状态。编辑者“资料不足，所以无法证明”的查证结论放正文外。
- 外部资料确认了原文未提到的细节，不自动全部补入；只有修复现有事实或必要歧义所需的部分才加入。

## 日记开篇选错了主角

原句以“今天的重量落在门铃项目上”起笔。如果材料只支持同事在旁边逐项过问题，只把“你筛了”换成“同事筛了”仍然把这场会当成了本人的一天。沿用原来的日记语气，用有本人直接行动的事情开篇，例如“今天反复追着问的，是镜头装好时清楚，为什么隔两天又糊了”。在适当位置留一句“晚上，同事在过门铃的问题”，具体条目放回会议分段。原文中准确的时间、过渡、其他自然段照常保留。

## 提交前的逐句检查

将原文与候选正文按自然段和句子对齐，不只看 API block 是否变化：

1. 每一处改动能否指出原句的具体错误或必要衔接？“更简洁/更客观/更像报告”不是订正理由。
2. 未涉及错误的原句、细节、时间顺序和段落是否还在？
3. 是否把核验渠道、证据评价、不能推断、不能等同等审校话语放进了正文？这些话如果原本就是当天对话内容，则另按实际语境判断，不能关键词批量删除。
4. 是否只是因为整篇在一个 block，就从头重新组织了一篇？应回到底稿逐句修。
5. 需要较大局部修改时，是否保留了周围正确句子，并在 evidence 解释范围？不要设机械的字符改动比例：同音错字密集与真正换文体不是一回事。

这一步是语义和文风复核。辅助脚本的版本、段落和请求校验不会自动检测这些问题。
