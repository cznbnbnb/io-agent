## 已发现并修复的问题

| 问题 | 本轮处理 | 验证方式 |
| --- | --- | --- |
| 电量变化或命令回显可能被误判为设置成功 | 仅比较本次命令涉及的读回字段，全部一致才确认；回显不作成功证据 | 设置读回回归测试 |
| 设置写入方法只入队就返回，发送异常被吞掉 | 返回并等待实际发送结果，错误交给调用方 | 发送失败、断连队列测试 |
| 重连后仍可能发送旧队列里的设置 | 用连接代次取消过期任务；断连清理缓存和读回计时器 | 断连/重连回归测试 |
| 当前配置未读全便用界面默认值写入组合设置 | 界面先读取；业务层拒绝不完整的组合设置基线；专注模式保留设备实际策略 | 部分读回、策略保留测试 |
| 设置被拒绝但读回 JSON 没变化，界面仍显示乐观值 | 完成校验时推进界面版本，恢复读回的真实值；校验期间暂停继续修改 | 不变读回与快速回执测试 |
| 连接阶段每次回报都触发业务恢复，甚至早于认证/状态就绪 | 在认证和状态均就绪时触发一次恢复，离开就绪状态时清理 | 连接状态边界测试 |
| 初始化和设备消息路由依赖页面是否打开 | 新增 `AppRuntime`，由 Ability 管理文件服务、设备消息和转写线程 | 生命周期与消息路由测试 |
| 自动服务循环没有停止入口 | 增加停止、取消计时器和过期回调保护 | 停止与初始化中取消测试 |
| 转写线程失败时可能回到界面线程执行大模型 | 主应用要求 Worker；缺失时明确报错；模型解包和识别按需开始 | 缺失 Worker 与委派转写测试 |
| 未知电源状态被当作已充电，触发自动转写 | 未确认充电时暂停自动任务 | 代码检查及完整测试套件 |
| 按留存策略清理音频后，仍存在的转写文字从列表消失且不能导出 | 录音条目允许仅保留文字，文字导出不再依赖音频；清理前重新核实文字存在且非空 | 清理/重载/导出和缺失文字测试 |
| 提词文件尚未完整就绪，眼镜提前的继续回报可能解锁控制 | 文件和提词业务两项就绪前，状态回报不能进入运行或暂停阶段 | 提前回报测试 |
| 眼镜暂停与手机开始/调速回执交错时，出现错误超时或旧状态覆盖 | 已完成传稿后的眼镜暂停状态优先保留；调速值等确认后再生效 | 交错、迟到和拒绝回执测试 |
| 地图没有加载状态，旧页面回调可能访问已销毁的地图 | 按组件管理原生地图生命周期、等待 SDK 延迟就绪回调再定位/绘制，增加 15 秒提示及手动重载 | 生命周期、异步回调及超时测试；实际白屏仍待真机复测 |

## 界面和组织方式

首页突出眼镜状态、连接操作和六项日常工具；底部固定为“首页 / 功能 / 资料 / 设置”。服务配置与协议调试收起到对应位置，连接诊断使用独立入口。

采用暖白、深绿和统一圆角/间距，提供配套深色资源。窄屏使用单栏，宽度达到 720vp 时首页采用双栏。系统安全区从窗口接口读取，替换原有硬编码顶部空白。仅挂载当前页面，避免隐藏页面覆盖单例回调。

具体功能页仍复用既有实现，录音、导航、提词器尚未全部重写。真机发现的卡片圆角覆盖问题已修正；设置读回结果移到顶部，并在完成时弹出提醒，避免操作后找不到确认结果。导航服务配置增加申请说明和按当前真实签名复制完整 App ID 的入口。

## 鸿蒙系统接口与眼镜接口的核查边界

- 当前是原生 ArkUI / ArkTS、Stage Ability 工程，使用鸿蒙蓝牙、窗口安全区、权限、后台任务和 Worker 接口。
- 已用本机 DevEco 官方 SDK 声明与原生编译器检查接口匹配。编译目标为 `6.1.1(24)`，最低兼容版本为 `6.1.0(23)`，并非使用 HarmonyOS 7 SDK 编译。
- 原有 BLE 传输已经有特征订阅、MTU 和发送队列，本轮保留已有协议实现并修复其上层状态和确认逻辑。设备命令字段来自项目已有资料/样本；没有取得可独立验证的 RayNeo iO 鸿蒙官方硬件 SDK，因此不能把编译通过当作固件协议验证。
- 部分继承代码中的“官方格式”“真机实测”等注释属于原开发资料，本轮没有重新验证这些声明。
- 自动转发其他应用的系统通知尚未实现。当前“文字通知”是向眼镜发送应用内文字；现有 module 配置没有通知订阅扩展，权限和分发资格也未验证。
- 高德原生导航仍需有效签名和对应 Key。完整签名 `appId` 用于申请 Key，不能仅凭包名或 Web 服务 Key 判断鉴权成功，依据[高德官方入门指南](https://lbs.amap.com/api/harmonyosnext-navi-sdk/gettingstarted)。

## 编译与验证

本机原生编译已成功，见 `build-check.log`；未配置签名的提示是预期结果。项目仍有继承的原生接口异常处理、废弃 API 和第三方资源警告，本轮未全部消除。

签名编译也已成功，见 `sign-check.log`。使用 `sign-windows.ps1` 时必须先运行 `build-windows.ps1` 同步并编译当前源码；签名脚本不会自行同步源码。

原基线测试为 284 项。0.1.14 完整测试为 **309 / 309 通过**，见 `refactor-tests.log`；0.1.15 为 **323 / 323 通过**，见 `offline-tests.log`。测试采用鸿蒙源码转译与平台模拟，不能替代真实蓝牙、GNSS、后台存活或镜片显示验收。

在 Windows PowerShell 执行：

```powershell
# 在 rebuild 目录中编译；DevEco 路径可替换为自己的安装位置
.\build-windows.ps1 -DevEcoHome 'D:\APP\DevEcoStudio'

# 仅在本机已有原签名配置且设备在调试描述文件中时使用
.\sign-windows.ps1 -SigningProject 'D:\Project\turboio-harmony\harmony-sdk'

# 在 rebuild/harmony-sdk 目录中运行测试，使用 Node.js 22
$env:DEVECO_HOME = 'D:\APP\DevEcoStudio'
node --test --test-concurrency=2 tests/*.test.mjs
```

本机 Hvigor 不接受中文工程路径，也会解析目录联接的真实路径。脚本将两个源码目录增量复制到真实的英文临时目录 `$env:TEMP/TurboIO-refactor-01a11` 后编译，再复制 HAP 回来。需要 DevEco、OHPM 可用，并可写入其正常依赖缓存。临时目录和依赖缓存不会被脚本自动删除。

安装包约 425 MiB，主要继承了打包进应用的离线模型。模型按需下载、包体拆分和模型解包写盘优化可作为后续工作。
