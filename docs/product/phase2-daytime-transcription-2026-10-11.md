# P22 日常短窗调度接入（0.1.28 候选）

日期：2026-10-11。上一基线 `1b81be8` / 0.1.27 已在隔离真机入口验证三窗识别、两次进程重启续接。本次把窗口能力接入 `RecordingService`，没有把上一轮真机证据扩写成日常采集共存通过。

后续隔离日常协调器真机实验已在0.1.30执行，收到熄屏音频但转写超时，详见[实际失败及取证记录](./phase2-daily-coexistence-2026-10-11.md)。以下0.1.28记录保留当时验证范围。

## 行为和实现

- `LifelogSession` 在建立分段时原子保存稳定开始时间；持续采集每新增至少300个已刷新/fsync的 OGG 帧保存进度并通知协调器。缓冲中的帧不公布，保持现有原音归档和轮转规则。当前源码默认按整点对齐、步长60分钟；另有10分钟区间参数，两者不能混写成“实际固定10分钟”。
- 修正轮转/重新握手通知使用新段开始时间的缺陷，旧段转写始终使用旧段的开始时间。元数据 v2 明确 sealed；异常退出留下的开放文件保留，列为“采集中断，待核对完整页”，不把旧进度0当作无音频，也不冒充已封口。
- `LifelogWindowPipeline` 每次处理334帧（20.04秒）核心、前后最多200帧（12秒）上下文，沿用真实 Worker 和前缀 SHA256 检查。文字窗口先不可变提交，再发布资料修订与旧格式文字；中断后可直接补发布，已完成窗不重推理。原音与文字目录相互独立。
- 自动智记不再以充电作为统一准入门槛。读取真实电量、温度、可用空间、前后台/蓝牙后台资格；低电、热限、未知信号或交互占用时延后，原音保留。手动 forced 不绕过这些护栏。原有主动录音封口链路继续复用，未在本批改为短窗。
- `TranscriptionMeter` 在派发前原子预留预算，识别后以系统单调时钟结算整个调用的实际经过时间，包括准备模型、前缀重放和识别。当前候选为滚动60秒最多20秒额度，单次 Worker 响应期限最多15秒；充电也保留该候选额度。进程被终止留下的预留在窗口到期前保留，重启不会获得全新额度。它是调度准入预算，不是操作系统对 CPU 的严格抢占上限。
- 开始主动录音或助手对话时中断正在进行的智记 Worker，并重建可用线程；保留已提交窗口，这类优先级中断不累积失败次数。热限、功耗和实际抢占延迟仍需真机验证。
- 分窗发布的 JSON 带 `transcription_complete` / `covered_frames` / `source_frames`。已有文字可导出，但整段处理完成前不计入每日总结的完成门槛；既有无该字段的文字保持兼容。跨窗聚类编号分开命名，不把两窗的“簇0”合并为同一个人；实名和“我”的识别保持未验证。
- 补齐连续杀进程绕过三次失败上限的漏洞：达到上限进入可见失败，保留原音；用户可明确重试。已封存结果即使处于最后一次尝试，也优先恢复结果发布。

## 未完成或仍需取证

1. 本批协调器与持续采集的真机共存、未充电运行、锁屏抢占/恢复、热限、低电和长段性能未验。手机最新实验入口能连接不等于这些场景通过。
2. 模型解包目前位于 Worker 派发前，虽计入整个调用预算，仍需优化首次准备的分块/中断与截止时间；不得把15秒 Worker 响应期限称为整个准备流程的硬上限。
3. 系统直接终止时的开放 OGG 目前保留并显式待核对，尚未自动从完整页恢复最后不足一窗的文字；不能称所有异常退出都已自动补完。
4. 大于16MB或60000帧的单段当前拒绝窗口处理。应在保持原音不变的前提下做分块索引，不能静默截断或通过缩短采集替代支持长段。现有按整点的最长正常段须现场检查实际字节/帧数。
5. 短窗的词句边界准确率、重叠语音、跨窗重复/漏字、P23人工校正后后续窗口的处理策略还需产品级验证；当前更正/删除保护继续拒绝自动覆盖用户版本。
6. 候选预算、20%低电阈值、热限与64MB空间阈值不是已验收的功耗指标；8小时与官方同场景比较仍未完成。充电精修尚未作为独立版本任务落地。
7. 服务器资料/备份确认、同步、真实 Agent 闭环、P13设计确认与官方基础功能验收继续保持原计划，P22不得凭本次构建通过标为整体完成。
