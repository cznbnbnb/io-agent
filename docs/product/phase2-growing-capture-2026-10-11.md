# P22 新采集共存与等待页缓存修复

日期：2026-10-11。对应 PRD 日常资料及白天产出文字要求；不更新用户的 Excel 进度快照。

## 修改及边界

0.1.43 的新采集日志暴露了一个独立于蓝牙连接的问题：首窗完成后，如果下一窗尚缺完整的未来音频页，`ASR_WINDOW_WAITING_AUDIO` 会进入通用异常清理，清掉已经验证的 PCM 缓存。随后音频增长，下一窗又从头重放 Opus。该等待是正常的流式状态，并非解码错误。

0.1.44 在确认窗口可运行之前保留原 OGG 索引及其 PCM 摘要绑定。只有正常等待新页跳过缓存清理；来源摘要变化、CRC 错误、读取异常、真正解码或识别错误仍拒绝并清理。没有放宽来源校验、剪掉原音、修改固件、主动绕过 A1 下发 A2，或增加收音开关重试。

新增实际转写代码回归覆盖：首窗完成 → 同一来源未增长及增长但仍不足的三次等待 → 新页足够后继续。下一窗喂给 VAD 的 PCM 逐样本等于独立从头解码，原生总解码 417 帧且只重置一次；等待期间没有新增解码。最后修改来源，仍明确拒绝。该分支目前属于电脑模拟验证，不能冒充手机实际经历三次等待。

同时去掉隔离实验页写死的旧版本号；扬声器脚本补 UTF-8 BOM，兼容 Windows PowerShell 5.1。此前一次播放因编码解析失败，没有执行；同轮随后使用当前 PowerShell 播放 25 秒。0.1.44 复测已实际由 Windows PowerShell 播放 60 秒，两次均回读确认音量从临时 25% 恢复原 100%，静音和默认设备未改。

## 0.1.43 原问题回查

自有实验进程一直存活，最初页面不可见实际由 USB 系统弹窗遮挡，并非进程已退出。关闭弹窗后连接为 ready。75 秒有限采集收到 A1，距开始 29.217 秒；A2 提交后 20.060 秒观察到首个音频包。该时间表示消息观察延迟，不能直接当作真实声音丢失时长。

原音封口 767 帧、46.02 秒、185169 字节，SHA256 `a0f77762059907045a9d7374556baeb726bfad09b3d39ac657c5ac4fec0100da`。36 个采样中 35 个确认熄屏，6 个同时确认采集意图和实际音频载荷；采集期间提交前两个窗口，但它们尚未产生归属核心窗的有效语句。首轮达到 180 秒实验期限时只覆盖到第 334 帧，不能称整段完成。

之后显式只恢复同一段转写，没有重开采集，最终五窗连续覆盖 `[0,167) → [167,334) → [334,501) → [501,668) → [668,767)`，队列清空，最终三条语句、资料 revision 8/text_revision 5。独立从手机取回隔离原件，核对真实 OGG 帧数、所有窗口的原音前缀摘要、token 核心归属及最终资料与转写正文一致；正文和原音仅在忽略目录。

## 0.1.44 新采集

同样为 75 秒隔离采集。A1 距开始 13.368 秒，A2 后 20.094 秒观察到首包；封口 1032 帧、61.92 秒。36 个采样中 35 个确认熄屏，9 个同时确认实际音频载荷与采集意图；采集期间已保存带识别语句的窗口，且一次采样同时看到收音与 Worker 作业。此轮实际支持短时间共存结论，不能外推全天。

首轮仍在 180 秒实验期限停止，覆盖到第 334 帧，余下原音与检查点保留；后续同段恢复单独记录。手机原生日志显示第二窗新解码 167 帧、复用 166 帧且未重置，证明该轮相邻窗复用生效；本轮首窗耗时超过 5 秒，下一窗先等待功耗预算，未实际经历电脑回归中的三次缺页等待，不将两类证据混同。
