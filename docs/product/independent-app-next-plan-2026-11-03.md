## 执行顺序与验收

### 1. 先核实耗电来源与独立身份兼容

按手机/电脑、接口和状态拆解请求，区分有效任务、空轮询、长连接重连、心跳及重复注册；核实后台管理页面是否计入相同统计。截图是全部设备 24 小时 102,577 次、正文 112 MiB、最近约 60 秒 1.38 次/秒、16 次失败，不能换算成手机 mAh。

优先检查手机熄屏且无任务时是否仍频繁唤醒，再处理重复轮询、失败退避和按变化通知，保留忙时及时投送。后台图表直接给出手机占比、空轮询比例、各主要接口，避免总量误导。沿用已有真实任务及推送测试，不能降频后让手机指令失联。

同时核对独立包 AMap 持续定位与地图/导航的身份问题；优先复用已有合适系统定位路径，涉及坐标系、路线跟随和耗电时先说明具体取舍。需要自己的第三方 Key 时明确登记要求，不伪造官方包/签名。用同手机、相近录音/佩戴/网络的原厂与 iO 分时对照测量，不能两包同时运行或以短采样冒充全天功耗。

验收：给出真实手机请求与唤醒基线、修改后同场景结果和消息延迟；天气、普通智记位置与导航分别记录通过/未通过。

### 2. 修复日历绿点语义与缓存

复现 10 月 30 日：核对原厂 calendar 的 hasLog、文本列表、轨迹/活动元数据及本地缓存。现有 OfficialLifelogCalendar 只把 hasLog 当日期提示；MaterialHistorySchedule 合并月份使用 addAll，旧提示可能保留，需复现而非仅据静态代码认定根因。

绿点表示“有可查看的资料”，不是“当天一定有文字”。有轨迹无正文时显示“仅活动/轨迹”；未核实和读取失败不能冒充有资料或无资料。若权威完整回读确认没有支持的数据，更新陈旧日期标记；不由读失败推断删除。月刷新只取轻量索引，其他日期按需读正文，仍只预载最近有数据三天。

验收：空日、只有总结、只有转写、只有轨迹/活动、缓存陈旧、断网六类；切换/重进不出现虚假绿点、不下载全年正文。

### 3. 活动、轨迹、日历扩展到服务器与 CLI

先做字段盘点：原厂位置并非都在智记文字中；已有 OfficialLifelogInsight.Day.trail、LifelogInsightStore 本地保存，也有原厂位置缓存/批次模型。复用已验证读取链，不重新建立一套定位采集。逐一确认真实步数/活动状态、停留点、轨迹、日历的来源与完整性；原厂没有的指标明确不可用，不把 GPS 路程伪装成计步或热量。

用户本次明确要求同步这些类别，覆盖之前“位置不上传”的产品范围，但本轮只计划。执行时按当前账号、日期、来源 ID 和版本增量同步，保存时间区间、时区、坐标系与精度/缺失状态；原音继续不上云。资料设置中分别展示活动、轨迹、日历同步开关和状态，不重新增加高频 GPS。仅处理用户自己的日历及已有授权资料，权限不足时正常申请。

CLI 按日期/范围查询这些结构化数据，daily 保持现有完整有效文字，并提供活动概览与详细查询入口；精细轨迹按需读取。日历“计划参加”与传感器“实际发生”分开，不能让 Agent 将计划写成事实。已有文字订正继续独立保存，不篡改原始位置/活动记录；注明采集来源和完整性。账号隔离、重复上传、断网续传和来源更新分别验收。

验收：同一天手机→服务器→CLI 的项目数、日期、来源版本一致；无原音、无新开采集，其他账号不可见；旧文字查询和订正不回退。

### 4. 悬浮工作区展示“这一天”

保留现有日期导航和紧凑列表，加入可折叠的活动概览、地点/停留时间线、轨迹预览、日历安排。默认收起详情，统一 Lucide 图标、间距、返回逻辑与加载状态。地图需明确坐标系，优先使用已有可用地图组件；暂不可用时显示地点/时间列表，不用空白地图假装成功。概览只显示实际有数据的指标。

验收：默认折叠、快速日期切换不卡、空日和仅活动日清晰，手势返回逐层退出；展示不触发额外定位或全量下载。

### 5. 设置中的更新中心，分两条链实现

**iO Agent 更新：可行，优先实现。** 电脑或 CI 取得官方底包后，由 Agent 按升级手册适配、测试、签成 iO Agent 包并发布；手机设置显示版本/更新说明，下载已验证成品，调用系统安装。不是在手机上临时拆包编译原厂 APK，也不是让原厂 APK 覆盖独立包。服务器保存发布信息和完整性摘要，不放私有签名密钥。以后每个新版是否已适配应明确显示。

**眼镜固件更新：已有固定版本基础，难度较高。** 当前 Fixed60Profile 只认识 Strix OS 1.0.5.5 的精确摘要及四处补丁，Fixed60OfficialGate 已有预检、单次授权、传输/重启回读。将这些能力统一收进设置可行，但不能把旧偏移套给新固件。每个新版先确认官方包、型号和基线，重新定位待办显示时间逻辑，离线修改重打包、审计差异及恢复方案，再发布“已适配”候选。用户看清版本和变更后主动点安装；不后台自动刷写。未知固件仅提示尚未适配。不能保证新固件始终允许相同修改或回退。

验收：手机只呈现匹配且已验证候选；错误包/下载中断拒绝安装；安装保留账号和资料；固件版本、电量、忙碌、断连和重启结果沿用真实门禁。补丁不可迁移时明确停在适配环节，不能放开安全校验。
