## 目标与现状

本轮交付三个实际可用的入口，支持 Claude Code 和 Codex：

| 目标 | 当前状态 | 本轮完成标准 |
| --- | --- | --- |
| 眼镜双击 AI，访问默认 Agent | 默认目标已保存，主动唤起未接通 | 双击、口述、确认后，由默认的已有会话执行；结果回到手机和眼镜 |
| 手机选择 Agent 的 session 下发任务 | 能选择已登记连接、将任务存到服务器；电脑执行未接通 | 指定会话实际收到并执行，原电脑对话可见，手机显示执行结果 |
| 打断并追加指示 | 只有明确标注未发送的本机草稿 | 停止指定任务正在执行的轮次；确认停止后，可在原会话按新指示继续 |

此前 R3 收口只覆盖“Agent 提问 → 眼镜回答 → 原任务继续”，不能据此认为本轮三项能力已经完成。

## 已确认的产品规则

1. **默认目标是一组明确绑定**：电脑、Agent、工作区、具体 session。手机可设置；CLI 登记时也可显式设为默认。修改默认只影响之后发出的新任务，已有问题仍回复原会话。
2. **手机选择实际会话**：按电脑、Agent 分组，显示会话主题、工作区、最近活动、空闲/执行中/离线状态。先建立电脑端会话发现与能力登记，再让用户选定并接入。只上传选择所需的元信息，执行指令只进选中的会话。
3. **忙碌时默认排队**：新任务显示“等待当前任务结束”。用户想改变正在执行的工作时，使用独立的“打断并指示”，避免普通提交意外打断。
4. **离线或目标不可用时明确等待**：显示具体原因，允许用户取消或手动换目标。指令有期限；重新上线时只恢复有效任务，不静默新建会话或换 Agent。
5. **打断是两步操作**：点击“打断”后立即发送停止请求，界面显示“正在停止”；收到原进程停止证据后显示“已停止”。用户可以随后填写指示，点击“按此继续”，在同一 session 开始新一轮。停止本身不要求先填写指示。
6. **眼镜主动任务沿用熟悉的口述确认**：双击 AI → 提示当前默认 Agent/主题 → 口述 → 确认 → 发出。继续采用 60 秒口述上限和确认卡，避免将错识别的口述直接变成电脑动作。结果以简短通知呈现，详情留在手机；Agent 需要决策时复用已有问答链路。
7. **状态必须有对应证据**：“服务器收到”“电脑收到”“执行中”“正在停止”“已停止”“完成”分别呈现。断线或回执不明时显示“待确认”，重连先核对原操作，不盲目重复执行。

## 实施顺序与阶段出口

### 1. 先验证真实会话控制接口

分别验证 Codex 桌面版和 Claude Code 当前使用方式的原进程控制接口：找到指定会话、读取当前执行轮次、下发输入、打断、取得终态和结果。保留用户当前会话的模型、权限和工作目录配置。

Codex 官方 App Server 有输入和中断接口；本机桌面版另有会话持有者与转发机制，尚未完成实际接入验证。Claude Code 的 SDK 输入/中断接口存在，但还须验证如何接入用户当前宿主中的原进程。接口存在不等于本项目已能控制。

**出口**：两个 Agent 各用隔离的可丢弃测试会话证明“收到一次输入 → 运行 → 实际中断 → 原会话继续”。同时验证工作进程及由它启动的受控子任务的停止情况。若某种宿主必须增加一次接入配置，先明确具体动作和支持范围，不能以另开一个同名会话替代接管。

### 2. 接通电脑桥接与手机会话选择

在现有一次配对和任务队列上增加会话发现、执行能力及在线状态。电脑端桥接只向已选定、已绑定的会话派发；新任务使用独立操作 ID，持久化执行映射和回执。

手机完善会话选择与默认目标页，接通“提交给 Agent”的实际执行与结果显示。默认目标与本次临时选择分开；排队任务可取消。

**出口**：手机选择两条不同的测试会话，指令分别只在对应原对话执行，手机收到各自结果。双击提交、网络重试和桥接重启均不重复执行；目标离线、已关闭或忙碌有明确状态。

### 3. 接通打断与追加指示

扩展任务控制事件，绑定原任务、session 和预期执行轮次。手机“打断”独立于“暂停连接”；暂停连接只是停止收发，不能假装停止电脑任务。

停止请求与停止确认分开。旧页面、延迟到达的指令不能误停同一会话后来开始的新任务。停止后保留上下文、历史和指示草稿；“按此继续”沿用原会话与原权限。

**出口**：运行中的受控长任务确实停止；过期或重复打断不会影响后续轮次；停止回执丢失后能恢复核对；追加指示在原会话实际执行。已完成的外部动作不会因打断自动撤销，界面表述限定为停止后续执行。

### 4. 接入眼镜双击 AI

先核对原厂双击唤起、语音识别结果及退出回调，再把主动口述接到同一任务下发入口。开始口述时固定所选默认目标，并在确认卡中保持一致；期间修改默认不改投这次口述。

手机前台、后台和熄屏走同一条路径。与已存在的问题提词器、任务口述、确认卡统一管理占用，明确提示当前忙碌，避免重复开麦或连续投放。默认目标不可用时保留可确认状态与失败原因。

**出口**：双击 → 默认目标提示 → 口述确认 → 指定原会话执行 → 结果返回的完整链路通过。覆盖重复双击、取消、默认目标变更和断网恢复，不重复发任务。

### 5. 合批交付与集中验收

先完成隔离自动化、实际宿主控制及开发者手机自测，再集中安排眼镜上不可替代的操作观察。只回归受影响的既有问答、确认和后台恢复路径。

手机仍以 dev92 为当前基线；开发完成且核对最新共享版本号后，按设备锁约定合批差异安装。核对安装前后完整 APK 哈希，保留稳定回退包。独立 Codex 工作区正常提交推送，交接记录注明真实验证范围。

**最终验收**：用户在手机选中 Claude/Codex 的已有会话并成功下发；打断运行中的任务后，原会话能按新指示继续；设置默认后，眼镜双击能够访问该会话并收到结果。必须分别记录三项端到端结果，不能以服务器入库或界面按钮可点击代替。

## 本轮最先解决的不确定项

最关键的是“连到正在运行的原会话”，尤其是 Claude 的不同宿主接入方式，以及停止后子进程是否仍运行。因此第一阶段先做有界验证，再扩展手机与眼镜入口。该阶段完成后报告两种 Agent 的实际可用范围、所需接入动作和证据，继续推进后续已批准步骤。
