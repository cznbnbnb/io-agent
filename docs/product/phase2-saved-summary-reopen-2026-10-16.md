## 正常入口与保留的行为

智记页选中日期后，使用独立的“已保存的每日总结”区域，显式点击“查看已保存”。目录每页最多10项，可下一页；只有当前来源可核对的项目能打开。打开后显示完整保存总结，保留模型正文内的二级标题，支持关闭及“导出已保存总结”。生成时间、模型和生产者在旧文件中没有可靠记录，页面不根据文件修改时间猜测，也不把目录第一项称为最新总结。

目录区、总结正文和状态属于独立页面状态，不占用普通记录正文、编辑器或[0.1.89本机查询](./phase2-local-material-search-2026-10-15.md)。改变查询关键词、说话人或清除查询不会清掉已打开总结；关闭总结也不清查询或无关详情。原时间线、录音/智记、转写、生成汇总、原文编辑、导出和删除入口保留。

采集字节数、阶段、转写进度或同步状态刷新不会反复扫描总结目录或重建整日输入。页面复用已有canonical成员及修订签名：真正更正、空正文更正、新增、删除、移除成员或当前资料读取失败时清理旧目录和旧总结正文；明确刷新、改日期、编辑回调、接受删除和离页同样使总结失效。用户须再次显式查看，不自动打开旧结果。

0.1.88的完整口述来源、草稿、恢复、outbox及停止门禁没有改动；本批只读命令不经过任务提交或收音端口。原建议卡两分钟连续可读问题未修复，H07已有开放事项和来源128条容量/安全回收边界不因本批关闭。

## 文件来源与严格校验

新增只读`SavedJournalSummary`核心。正常页和debug服务使用RecordingService导出的同一实例，以实际`buildJournalDay(..., '')`取得当前无总结输入。目录只认选中日既有完整MD：`day-YYYY-MM-DD.md`日缓存和内容摘要命名的独立快照；忽略`.partial`及无关文件，不删除、迁移或改写原文件。

打开条件沿用实际`bindJournalSummary`写入格式：完整无总结输入的SHA256、总结插入前的前缀、之后的完整原文后缀、顶层日期及快照文件全字节摘要必须一致，总结块非空。原文或总结可以包含`## AI 总结`及其他标题，不能靠寻找下一个二级标题截断或判断来源；纯原文汇总中的字样也不能当成真实AI总结。

每次打开及CLI每次分段读取都重新读取文件和当前来源。资料修订变化、删除、缺失、实际渲染正文变化或文件被替换后，旧引用不能通过读取历史修订或旧ASR复活。校验绑定的是实际生成输入；同修订破坏中只有不影响该输入的冗余字段变化，不应虚称已改变总结来源。

目录仅返回元数据，不带旧正文或片段。状态分别说明：

| 状态 | 可否打开及含义 |
| --- | --- |
| `current` | 本次读取的来源与保存指纹完全一致，允许打开 |
| `stale` | 当前输入已变化，需按原生成入口重新生成 |
| `unverifiable` | 旧总结没有可验证的来源标记 |
| `not_summary` | 只是原文汇总，没有已验证的总结块 |
| `corrupt` | 日期、摘要、UTF8或结构校验失败 |
| `unreadable` / `source_unavailable` | 保存文件或当前来源暂不可读取 |

非`current`项目不返回旧正文；无法读取不是“当天没有资料”。无来源可核对的旧格式也不会仅显示警告后照常打开。未引入历史日自动过期政策。

读取使用真实Kit文件接口、只读句柄、短读循环、长度与EOF核对、严格UTF8和字节回编码检查。单次最多处理128个候选文件，保存文件累计最多4Mi UTF16单位；当前输入及单文件正文各最多2Mi UTF16单位，单文件原始字节最多8MiB。达到边界或遇到不可读资料时返回`incomplete`和原因，不把局部目录说成完整目录。分页游标绑定文件成员、实际文件内容/状态与当前来源快照；目录或来源改变后旧游标拒绝，须重新查看。

## 再次导出的异步保护

“导出已保存总结”先以当前引用重新`open`，核对完整MD及来源指纹，再用现有`writeJournalSnapshot`准备按内容摘要命名的不可变导出源。系统选择器拿到的是该快照，不是可能被自动汇总或原文上传覆盖的可变日缓存。

`copyOut`增加可选守卫，旧调用默认允许，既有导出行为保留。新入口在选择器返回后、任何目标文件`open/TRUNC`或首字节写入之前，再次核对当前日期、页面代际、前台、总结引用和来源，并重新`open`保存总结。等待期间资料删除、同修订实际正文变化、选中缓存被原文覆盖、改日期、关闭总结、离页或进入后台，都不能把先前选择直接截断写入目标文件。

实际复制采用短写循环，每262144字节让出事件循环；后续块和结束前只检查轻量页面/引用/来源签名，不每块重扫目录或重新构造全天输入。收到资料变化通知后中止且不报告完整导出。目标已写部分不能冒称回滚或原子恢复，App内原件保留。期间打开的普通详情、查询和新页面不会被迟到导出结果覆盖。

## 同一底层的schema6 CLI

现有App私有debug收件箱新增只读动作`list-summaries`和`read-summary`，调用同一实例的`list/chunk`。schema1–5和0.1.89查询保持；summary参数不能混入其他动作，日期、关闭式ID、摘要、游标、偏移和页大小在传输前校验。不会根据调用方提供的路径打开任意文件。`reconcile`仍只对账，不重发旧命令。

```powershell
python tools/phase1/io-card-cli.py list-summaries --summary-day 2026-10-15
python tools/phase1/io-card-cli.py read-summary --summary-day 2026-10-15 --summary-id '<目录返回的summary_id>' --summary-sha256 '<目录返回的content_sha256>' --offset 0 --max-chars 4000
```

第二条中的ID、摘要须替换为实际返回值。`list-summaries`接受日期、1–10项页大小及目录游标；`read-summary`按相同全文引用读取**完整保存MD**的一段，不是固定长度预览，也不只读取总结摘要。结果明确`total_utf16`、`offset`、`next_offset`及`has_more`；请求`max_chars`为2–4000个UTF16单位，实际返回可因EOF或代理对边界小于上限，不能从代理对中间开始或在中间截断。调用方在`has_more`时按同一引用继续，拼接原样内容并核对全文UTF8字节SHA256；后续文件/来源变化即拒绝，不拼接两个版本。

CLI保持原有2048字节序列化命令上限，App保持原有2048个UTF16单位的原始命令检查及65536字节结果上限。只暴露约定错误码，不把原始异常路径、旧正文或凭据拼入错误。完成态只表示本地只读命令完成，不表示眼镜显示、网络同步、用户回答或Agent任务完成。实际运行仍需App debug入口和可用本机HDC；本批Python测试全部Mock HDC，没有手机实测。

`read-summary`明确返回私人完整MD分段，结果具有敏感性；没有自动上传给服务器、模型或搜索引擎，开发证据仅使用合成内容。
