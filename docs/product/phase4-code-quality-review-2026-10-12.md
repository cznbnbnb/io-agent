## 1. 评估结论

**交付确有实质进展，资料服务、查询和队列基础值得复用；连接程序仍属于需要补强的实验原型，不能按正式 Agent 执行通道验收。**

优点：组件边界清晰，查询 skill / CLI、常驻连接程序、适配器进程层没有混作一个能力；使用真实 SQLite、事务、修订 CAS、幂等账本和受限 scope；部署独立服务，未把 iO 功能侵入已有站点；记录了失败的真机联网结果，没有将其写成成功。

不足：原有测试偏重正常路径。原套件全部通过时，路由隔离、身份切换、伪成功回执、运行时交付窗口、提问上传失败、服务端取消及回执归属仍有缺陷。网络去重和运行时执行去重被部分文字描述混同；“HTTP 成功”“回环联调通过”“真实 Agent 原任务继续”必须分别判断。单实例、期限裁决、真实 Hermes 恢复和长时运行仍未完成。

质量分级：**可继续迭代并受控联调；不具备日常自动执行真实任务的放行条件。** 不用测试数量或未经量化的百分比替代产品验收，也不据此降低官方基础体验要求。

## 3. 本轮修复与复现证据

前五类、提问恢复两类、消息/关闭回调及服务端三类均先运行反例，观察失败，再修改代码转绿。其他保护用新增回归验证，不虚称全部都做过修复前反例。

| 风险 | 接手代码的行为 | 本轮修复及验证 |
| --- | --- | --- |
| P1：错电脑/Agent 投递 | 所有可读任务都可进入同一个适配器 | 执行配置必须绑定 computer/agent，只交付匹配路由；project/session 保留给真实运行时继续核验 |
| P1：只观察消耗任务 | can_execute=false 仍可被自定义适配器返回动作绕过，并推进游标 | 不调用执行方法、不写队列事实、不推进游标，后续真正执行者仍能取到任务 |
| P1：账本跨身份复用 | 仅绑定 server_id，同服务器的其他 owner 可复用文件 | schema 2 绑定 server/owner/producer/computer/agent；凭据运行中更换也重核身份；非空未绑定旧账本拒绝自动接管 |
| P1：假成功丢事件 | HTTP 200 的无关 JSON 可被当成功并清 outbox | POST 与事件查询必须匹配 event/object/revision 和 server_stored 回执；伪成功保留事件 |
| P1：崩溃后重新执行 | 调用运行时发生在已处理标记之前，结果不明时会重新投递 | 调用前持久化 prepared、动作返回后存 responded；同一交付结果不明则 DISPATCH_UNCERTAIN，不自动重投；真实子进程硬退出反例通过 |
| P1：重启绕过永久拒绝 | blocked 只在内存 | 永久拒绝落盘，重启仍阻塞并保留原信封 |
| P1：后续修订抢发 | 同一批动作可生成冲突修订；前项退避后后项可能先发 | 按本地待发最高修订顺序生成；同对象前项未发时后项等待；503 后观测发送序列为 2、2、3 |
| P1：等待答复丢失 | 请求 POST 延迟、GET 404 时直接删除等待记录 | 未落库但仍有 outbox 时保留；重启上传成功后可接答案一次；已确认问题消失则停止并保留记录 |
| P1：合法回调动作丢失 | message 与 onRequestClosed 返回的动作被静默丢弃 | 统一经过持久交付记录与动作应用；消息接收回执及请求撤回后的适配器回执反例通过，不自行推断任务已取消 |
| P2：状态查询有副作用 | status 启动适配器、联网并保存账本 | status 完全本地只读；凭据缺失/服务不可达时仍可检查本地状态；不创建账本、不启动配置中的进程 |
| P1：初始任务假完成 | revision 1 可声明 running/completed/cancelled | 初始任务必须 queued，否则 STATE_CONFLICT；拒绝后不产生队列提交 |
| P1：取消后仍收答案 | 父任务取消中/已取消仍可接受问题答案 | 新答案检查父任务和 route；取消中、终结及 execution_unknown 拒绝 TASK_CLOSED；已有答案不会被删除 |
| P1：回执串对象 | receipts 只按 subject_id 查询，同 ID 不同 kind 混入 | 按 subject_kind / subject_id 查询，历史事实保留 subject_revision；相同 ID 碰撞用例通过，不把版本 1 回执改写为版本 2 确认 |
| P2：响应与错误边界 | 响应先整体读取才限长；适配器原始错误可能进入诊断 | 流式限制 1MiB、JSON/UTF-8 检查；适配器 stderr 排空丢弃、外部错误只输出受限码；停止后的适配器不作为成功 |

桥接器还整体校验已覆盖的动作后才保存 outbox；无效的后续选项不会留下前面动作的半截事件。CLI 配置相对路径统一相对于配置目录，拒绝未知/重复参数。

**运行时不明结果保护不是自动恢复保证。** 它针对同一持久交付键阻止自动重投；尚无单实例锁、运行时操作 ID 对账、跨修订事实裁决。不能把当前保护改写为全局 exactly-once、任务已恢复或已取消。

schema 1 非空账本不会被清空或自动转换。需要核对原身份、outbox 和运行时事实后建立专门迁移流程；不能删除状态文件来绕过不明结果。

## 5. 尚未关闭的质量门槛与继续开发范围

1. **P41 单实例与不明结果恢复**：账本无进程互斥锁；两个进程可各自加载旧状态并交付。加入独占运行所有权、重入保护与进程退出测试；为 prepared 提供可审计的运行时查询/人工裁决流程，禁止自动删除后重放。
2. **P42 真实 Hermes**：先核对固定版本支持接口，再实现严格 project/session 路由、忙时追加、取消、重启恢复。已有研究指出管理 gateway.sock 不等于会话 API，auto-continue 可能重投 prompt；不使用模拟终端输入或悄悄创建新会话。先用隔离无外部副作用任务验证，真实提问结果需回原任务。
3. **P40/P44 完整期限/取消**：当前请求随时间过期并不自动形成持久 expired 状态，bridge 可能继续等待；需统一有效期限、迟到消息、取消与答案竞争，以及 runtime operation ID 的去重/对账。TASK_CLOSED 修复只关闭一类新答案入口，不表示取消已执行到 Agent。
4. **边界校验**：适配器动作、响应对象、账本内容尚非全面 Schema 校验；须补字段上限、嵌套/重复键、跨请求关联及畸形协议用例。健康/备份诊断仍有 database_version=1 的硬编码，实际队列 DB 为 v2，需更正诊断信息。
5. **部署与 P31 联调**：本轮本地服务端补丁先保留审阅与回归证据，后续按既有独立服务流程备份、更新、核验哈希和回环，再做公网/手机联调。不得把四个未变文件匹配解释为整个线上版本已更新；不改已有站点。
6. **官方体验及长期验证**：后台锁屏、蓝牙/网络重连、积压、段内说话人、原音保存/上传、凭据续期、8 小时与功耗仍按原计划补齐。既有录音继续复用，不能因本轮聚焦服务端而将官方基础要求降级。

下一步先完成 P41 的独占运行与不明结果门槛，再推进 P42 隔离真实会话实验；公网和手机任务只暂停依赖连通性的部分。开发顺序仍以 PRD / DEVELOPMENT-PLAN 为准，本文为复审结果及当前修改说明，不另立优先级体系。
