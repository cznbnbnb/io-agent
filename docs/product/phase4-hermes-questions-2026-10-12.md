## 用户可观察行为与实现

后续接入后，Agent 提问可先持久保存，再由连接程序发送；回答必须匹配原 operation/task/project/session/request，不可送入任意窗口。当前实际交付为组件代码，还未对日常使用启用：

1. `runtime_journal.py` schema 2：身份校验后事务迁移，保留 schema 1 的领取与事件；新增 questions 表。问题与延迟 request 事件原子保存，稳定键重放不会再造问题，改变同键正文/期限拒绝。
2. `question_tools.py`：实际 MCP stdio 服务，仅 ask_user / wait_answer。私有配置固定已有操作和账本；模型不能选择会话/任务、领取操作、写答案或执行任务。等待最长 30 秒，可以重复读同一 request；取消工具调用保留等待事实。
3. 适配器侧答案保存：首答事务写入、同答可重放、第二个冲突答案拒绝；校验 request_revision / runtime_request_id / 原任务路由和选项。此方法需要后续接到经认证的服务器读取结果，本批实验的答案由合成测试端提供。
4. Bridge request 动作可携带 expires_at，信封保留原期限；离线重试不延长期限。原同步动作省略该字段时继续使用原一小时策略。只改电脑侧，不改变已准备发布的服务端补丁。

## 期限与恢复语义

服务器接受答案的时间和电脑收到答案的时间不同。问题的本地期限经过后，工具返回 deadline_elapsed，保留 pending 等待服务器裁决；不能把它写成“用户拒绝”。只要经认证服务器给出的 stored_at 早于问题期限，晚到的已接受答案仍可保存。服务器确认撤回/过期由适配器关闭等待；操作已结束时工具报告 operation_closed，不能用迟到答案重新执行。

目前未实现自动撤回、完整生命周期对账或长期归档。问题事件已过期但尚未被 bridge 接管时，bridge 保留并拒绝继续；这保护期限，尚不是自动恢复完成。模型和工具进程不负责直接修改云端请求。
