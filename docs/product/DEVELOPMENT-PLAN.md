官方基础体验贯穿全程，是独立验收线。它从阶段 0 开始盘点、阶段 2 集中完善、每阶段回归；阶段 7 做最终核验。正式版不允许以增强功能抵消基础缺失。

**本阶段不做**：连接真实执行工具的自动决策、所有 Agent 通用适配、自定义固件、完整精细动画。

**本阶段不做**：为了接 Agent 重写已验证设备协议、建立复杂人物画像、未经确认自动清理旧资料。

## 6. 阶段 3：服务器先成为可靠资料站，Agent 先能查

### 任务（建议执行顺序）

1. **P30 存储与查询服务**：落实 P14 的资料接口；接收文字/元数据、按配置保存原音、按日期/关键词/说话人查询；服务完成本地或测试环境验收后再按实际部署流程上线用户服务器。
2. **P31 手机增量同步**：持久化发送队列、校验与服务器存储确认、重试去重、积压显示；文字与原音独立调度，支持网络策略。
3. **P32 修改/删除与补传**：提供游标、分页、修订和删除事件；断网和重启后恢复；不让迟到的旧数据覆盖用户更正。
4. **P33 日常资料查询工具与 skill**：先有真实查询工具再写调用说明；至少支持按时间查询、按关键词定位、取原文、获取增量变化及来源引用。
5. **P34 综合分析验收**：本地 Agent 通过既有办公消息能力和日常查询工具，解释一组真实的承诺/时间冲突；生成结果可回存 App。

### 完成条件

用户当天的一段对话真实出现在服务器；电脑本地 Agent 能查询并引用它，结合办公消息给出分析；电脑离线不阻塞手机保存与同步。修订/删除能被查询方感知。

这是第一个增强里程碑：**电脑 Agent 能了解我的日常**。此时不承诺眼镜远程控制已完成。

**本阶段不做**：在服务器再部署一个自主 Agent、让服务器执行电脑任务、优先建设大而全的管理后台。

## 7. 阶段 4：先用文字把电脑任务接通

这一阶段必须先于正式眼镜决策流。否则 Agent 收到答案后如何继续原任务仍无实现基础。

### 任务（建议执行顺序）

1. **P40 可靠消息队列**：实现命令、问题、答案、结果的持久化与状态；设备/Agent 分别鉴权；大文件上传不阻塞短消息。
2. **P41 电脑常驻连接程序**：出站连接服务器、在线与可执行状态、掉线补拉、重启恢复、去重和错误对账。
3. **P42 首个运行时适配器**：落地 P11 通过的 Hermes 候选路径；明确目标电脑、Agent、项目、会话，支持能力声明；原会话不存在时返回错误，不悄悄新建替代会话。
4. **P43 手机文字委托与待答页**：通过简单真实输入完成“发任务—电脑执行—提出问题—手机回答—原任务继续—结果返回”。这是正式共享会话逻辑，后续眼镜复用。
5. **P44 失效和取消**：忙时队列、任务期限、取消请求/取消成功区别、执行状态不明时对账、两个终端回答竞争。

### 完成条件

使用一个可撤销的测试任务，手机输入能到指定会话；关闭并重启连接程序后，任务/问题/答案不丢失、不重复执行，回复仍回到原任务。数据查询 skill 与任务适配器互不混淆。

**本阶段不做**：用向任意终端窗口粘贴文本代替会话接口、一次适配所有 Agent、尚未接通任务就先做眼镜端漂亮进度动画。

## 8. 阶段 5：Agent 通过眼镜请求决定

### 任务（建议执行顺序）

1. **P50 通用请求工具与 skill**：在 P40–P44 上封装 notify、ask、get_reply、update/cancel、report；结果返回稳定请求 ID，等待由持久队列/连接程序处理。
2. **P51 原厂二态建议卡适配**：复用 P10 的已验证结果，关联 suggestUID 与 request_id/版本/会话；独立处理 type 33/34/35，核对原厂按钮和动画是否会误导成“加入待办”。
3. **P52 旋钮与头势**：仅启用实测通过的映射；验证焦点、短按、点头/摇头语义及误触；不能把语义接受当成原始点头事件。
4. **P53 眼镜自由语音回复**：绑定正在处理的问题，手机转写，保留附加条件，允许重说/取消；完整文字回原任务。能否在卡片中直接进入语音由 P10/P12 结果决定。
5. **P54 请求队列与共存**：稍后、撤回、超时、勿扰、离线、手机同时回答，以及智记/录音/字幕中的显示占用；默认不抢正在回答的焦点。

### 完成条件

Agent 发起问题 → 眼镜正确展示 → 用户选择或语音回复 → 本地 Agent 在原任务继续 → 眼镜收到相应反馈。正常、拒绝、附加条件、过期和重复事件均有完整记录。

原厂多选能力若仍未通过，二态决策可作明确标识的实验成果；PRD 的多选需求保持未完成，不自行宣布缩减范围。语音或手机兜底不等同于旋钮多选完成。

这是第二个增强里程碑：**Agent 随时能通过眼镜问我，并得到可用答案**。

## 9. 阶段 6：眼镜一句话委托电脑 Agent

### 任务（建议执行顺序）

1. **P60 接入已有助手入口**：复用现有唤起/收音和手机转写，把稳定文字交给 P40 命令队列；不再建设第二套任务通信。
2. **P61 指令与回复分流**：有活动问题时默认归属该问题，显式新任务时按新任务处理；“停止录音、关闭卡片、取消电脑任务”语义分开。
3. **P62 会话上下文与澄清**：默认电脑/项目/Agent 可见；含糊指令澄清、忙时补充或排队、电脑离线和指令期限处理。
4. **P63 眼镜任务反馈**：已识别、已提交、已送达、执行中、等你决定、完成/失败；长产物留手机与电脑，镜片显示短内容。

### 完成条件

用户一句话进入正确本地 Agent，会查询需要的日常资料，执行中通过阶段 5 询问用户，最后返回实际产物。电脑离线、会话丢失和取消都不会显示假成功。

这是第三个增强里程碑：**眼镜成为电脑 Agent 的随身入口**。

## 10. 阶段 7：完整官方对齐与日常使用验收

### 任务

- **P70 官方对照逐项关闭**：所有 BASE 差距逐条回查；仍需官方 App 的维护或权限受限项明确列出，不擅自忽略。
- **P71 全天稳定性**：8 小时场景、锁屏、切 App、断网、蓝牙重连、电脑重启、语音插入、重复回答、任务取消与数据恢复。
- **P72 功耗与性能**：与官方同场景比较手机/眼镜耗电、温度、延迟和流量；优化热点，不用关闭关键功能来制造好数据。
- **P73 鸿蒙视觉与适配收口**：以已确认设计规范验收深浅色、材质降级、大字、折叠切换；其他设备形态按确认的交付范围分别记录。
- **P74 安装升级与资料保留**：验证覆盖升级、既有绑定/配置/资料保留、版本说明与回退边界。

### 完成条件

PRD AC-BASE、AC-REC、AC-MEM、AC-QUERY、AC-ASK、AC-VOICE 等适用门槛全部具备证据；不支持项必须形成明确的范围决策。此时才称“可正式替代官方的版本”。

## 12. 第一批交给开发 AI 的具体任务

第一批仅包含：**P00–P02、P10–P12、P14**。P13 同期准备设计方案，后续在批量改界面前确认。这里的“同期”描述可独立推进的工作，不表示已创建其他 Agent 或聊天。

第一批交付清单：

1. 当前项目能力与官方功能差距表，明确已有录音复用入口。
2. 原厂弹窗/旋钮的真实能力结论，以及隔离测试的操作回传证据。
3. 固定版本下本地 Agent 的投递与原会话恢复实验结果。
4. 鸿蒙后台接收与转写初步记录，给出原始观察和失败条件。
5. 三组最小接口契约与正常/重复/过期/离线样例。
6. 下一批 P20–P25 的具体修改范围，说明依赖及仍受阻项。

本批不能用模拟数据冒充真机结论；设备暂不可用时可以完成代码阅读和隔离组件，把硬件项明确留为待测。不根据文档计划自动刷固件、替用户执行真实业务任务或将未完成能力上到日常环境。

## 13. 每个开发任务的统一交付格式

每项只围绕一个可验收结果：任务 ID 与需求依据 → 前置条件 → 修改范围 → 用户可观察行为 → 异常和恢复 → 验收步骤与证据 → 剩余问题。

区分代码完成、模拟通过、真机单项通过、端到端通过和日常验证通过。阶段切换依据出口条件，不依据新增页面数、测试总数或开发 AI 的“已完成”总结。

暂不写死工期。阶段 0–1 的结果出来后，再依据实际功能差距和设备/运行时限制估算，避免把未知协议工作当成普通页面开发。
