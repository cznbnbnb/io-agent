# 智记文字同步与服务器订正

更新于 2026-11-02。本批由用户批准扩展文字同步范围，并要求按天查询完整文字。服务器、共享 CLI 和管理后台已发布；手机 dev163 已签名，尚未安装，真实转写上传验收待调试连接恢复。

## 使用方式

已配对电脑使用 `cz-iot-cli daily`，输入 `{"date":"2026-11-02"}`，默认自动收齐该日已同步的每日总结、分段智记和逐字转写。日期使用来源日期，不改成电脑时区；不要求 Agent 逐段调用。`kind`、日期范围、关键词和显式分页保留为可选项。

| 命令 | 用途 |
| --- | --- |
| `daily` | 读取、搜索当前有效文字；订正段只返回订正版 |
| `daily-correct` | 根据明确依据订正指定段落 |
| `daily-note` | 补充后续进展，保留当时的原话 |
| `daily-history` | 明确查阅原文版本、作者、依据和修改前后值 |
| `daily-revert` | 撤销指定一次订正或补充，保留无关修改 |

完整输入示例及错误处理见 [CLI 用法](../../rebuild/agent-bridge/questions/DAILY-SUMMARIES.md)。管理后台“日常智记”可切换三类文字，继续使用紧凑列表/卡片；详情可查看有效文、原文与订正历史，并在确认后撤销指定修改。

## 数据流与一致性

手机原文和服务器订正分别保存。手机后续刷新只产生新的原文版本，不能覆盖订正；新段落正常追加。同一段原文发生变化时，保留订正版并标记 `needs_review`。订正不会下发到手机。

每次修改携带原文版本、订正版本、请求 ID、Agent 标签、原因和依据。服务端另记真实调用身份、时间与前后值。重复请求不会重复修改；另一 Agent 已改动时返回冲突，调用方重读后处理。撤销只影响目标修改，若同段后来又被修改，则拒绝覆盖。

转写订正会使关联分段总结及当天总结失效，普通查询暂不返回旧总结正文。Agent 可依据订正后的全文重新订正总结，并提交对应的 `dependencies_version`。系统不会自动付费调用模型；也不会把手机重传的旧总结视为已经校正。

旧的 `/daily-summaries` 读取端在账号存在订正时要求升级，防止其他 Agent 绕过有效版本继续得到旧文字。新的只读和订正权限只授予正式配对电脑；旧单会话凭据不自动扩大权限。

## 手机同步范围与开销

- 只上传明确列出的标题、摘要、主题、转写、时间和说话人。原音、音频 URL、位置、原始响应 JSON 不上传；不使用 ADB 或 Tailscale 提供产品文件访问。
- 后台读取仍为最近有数据的三天；其他日期在用户浏览并读取后参与增量上传，不全量回抓历史。已核实删除的本地记录不作为新资料重传。
- 独立账本按原文内容哈希去重，每轮最多处理八份变化资料；丢失上传回执时先核对服务器哈希，不重新制造版本。没有增加后台调度频率。
- 首次升级会上传已有缓存中的文字，因此服务器存储和首次网络用量会增加；后续只传有变化的资料。原文版本与订正历史保留，存储会随有效修改增长，本批不自动清理历史。
- 单份源文字最多 4 MiB，单次订正请求最多 1 MiB。查询内部每页最多 8 MiB，CLI 按天自动合并最多 32 MiB；超过时明确失败，不静默截断或伪称完整。历史也按字节分页。

`complete=true` 只表示服务器查询已取齐，不代表手机所有历史都已上传。旧缓存中已被旧版截短的分段摘要，需要重新打开对应日期刷新后才能恢复。
