# P20–P22 基础数据与恢复增量

日期：2026-10-11。候选 0.1.26；沿用现有录音、智记、模型和连接实现，不批量重画产品页面。此前硬件能力、接口与官方功能差距仍以首批交付记录为准。

## 已落代码

- P20：采集/转写协调循环改由 Ability 启停；导入模块不启动业务。销毁时释放周期任务、连接订阅和远程总结，旧线程完成不得回写新一代状态。停用默认按天清理原音；仅有转写成功不再足以触发清理。
- P21：新增 `MaterialStore`，在独立旁车目录迁移旧资料，不移动或删除旧原音、文字。按原始录音/智记 ID 生成稳定资料 ID；不可变修订、文本版本、句子 ID、来源/声道/同步状态；更正保护、版本冲突和删除墓碑。日常录音同时保存结构化转写和原 Markdown。
- P22 已实现部分：`LocalAsrQueue` 持久化任务、尝试次数、下次运行、错误及取消状态。识别结果先单独落盘，再提交资料和旧格式文字；写回失败后重试复用结果与逻辑任务 ID。推理失败最多三次并退避，重启恢复未完成任务；自动发现不复活已取消任务。失效线程可在下一次任务重建；全段处理有五分钟响应上限。
- 底层修复：录音、智记、语音的 Opus 状态由各 NAPI 环境独立持有，退出时释放，防止主线程封装录音重置转写 Worker 的解码状态。

本地旁车和队列的数值 `schema_version=1` 是私有落盘格式；尚未实现 P14 `1.0` 网络对象转换，不把它称作已同步。
