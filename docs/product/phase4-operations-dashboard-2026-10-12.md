用户确认此前成功访问的是 `http://cznbnb.cn/`。本轮直接 TCP/HTTP 探测不使用 Windows HTTP 代理：80 可连接，HTTP 首页为 200，没有 Location 跳转；443 超时。Windows 当时仍登记代理 `127.0.0.1:7890`，但直接连接也失败，不能仅归因于 Clash 规则。

只读 SSH 核对：nginx 监听 80/443；原网站仍代理到 127.0.0.1:3000，iO 路径 `/io-api/v1/` 代理到 127.0.0.1:3401/v1/。旧备份只有 HTTP，新配置追加 HTTPS，没有全站强制跳转。服务器本机 HTTP 首页 200、验证证书的 HTTPS 首页 200、HTTPS iO 未认证接口 401。UFW 和 IPv4 规则中已有 443 允许。

用户随后提供腾讯云轻量服务器防火墙截图：实例公网地址 43.142.59.131，入站列表仅 TCP 22、TCP 80、ICMP，没有 TCP 443。这是当前最直接的缺失规则证据，尚未以添加规则后的公网复测确认因果。下一步应核对实例，添加单条 HTTPS TCP 443 允许规则，保留已有规则；手机漫游需全部 IPv4 来源时应明确其公网暴露范围。不要使用“一键放通”。浏览器修改公网访问须遵守工具的动作时确认要求。

## 只读管理后台

新增隔离入口 `GET /v1/admin`，未来沿现有反代可访问 `/io-api/v1/admin`，无需把原网站首页改掉。当前入口只在本机测试，生产版本没有这些静态文件或接口。页面显示：

- 按已认证 producer 统计请求数、上传/下发正文 UTF-8 字节、HTTP 失败数；不凭名字判断设备是否在线或可执行。
- 当前任务/问题/消息状态数量、分别记录的回执阶段数量。
- 最近 50 次请求和最近 50 个队列修订，不显示任务命令、提问内容或答案正文。

`GET /v1/operations/summary?hours=24` 需独立 `operations:read` scope，hours 允许 1–168，默认最近 24 个小时分桶，按凭据 owner 隔离。原手机/电脑凭据不会自动获得管理权限。该权限不含资料正文读取、投递任务、改状态、取消或删除。页面外壳公开但不含业务数据；接口仍鉴权，不开放 CORS。

Bearer 经 Authorization header 发送，禁止查询参数；页面只在 HTTPS 或本机 loopback 使用凭据。令牌只保留在 JS 内存，连接后清空输入框，退出清除统计并中止请求；不使用浏览器持久存储。静态资源 no-store、nosniff、限制 CSP 和 frame-ancestors。错误只返回受限代码，不暴露 SQL、正文、令牌或异常堆栈。生产管理凭据尚未签发。

### 统计口径与恢复

服务端 `traffic.mjs` 使用独立 `<主库路径>.traffic.sqlite` 侧账本，绑定主服务 server_id，不迁移主资料库。CLI serve 自动启用；直接调用 `listen()` 的其他宿主需显式传入账本。

统计为已认证请求实际读入的正文和服务端生成的 JSON 响应正文；不含 HTTP/TLS 头、重传数据包、网站其他流量或尚未实现的原音对象上传。提前因 Content-Length 拒绝、尚未读入的正文不计；未经认证请求不计；管理 summary 自身不计；同一事件重试每次都计流量，但业务仍只落一次。

响应字节只证明服务端准备了响应，不证明手机完整收到、更不证明眼镜显示或 Agent 执行。耗时在序列化响应后、发送响应前采样，非客户端端到端时延。

小时汇总保留 30 天；逐次记录保留 2 天且全库最多 10,000 条，启动及每 128 次记录清理。查询 7 天时可能只有最近 2 天的逐次记录，汇总仍按小时读取。窗口包含当前小时，不是精确滚动 24 小时。所有删减仅限侧账本，不清理主资料、事件去重或队列历史。

侧账本写失败不会把已提交业务变成上传失败，summary 提示 write_errors；侧账本启动失败也不阻断主服务，保留问题文件、告警 TRAFFIC_UNAVAILABLE，并返回 available=false / initialization_failed=true，页面明确显示不可用。write_errors 是该进程累计健康计数，重启归零，不是永久完整性证明。统计可能缺失，不能用它作为业务确认账本。

主库 backup 命令只备份主库，不包含统计侧账本。侧账本需另外采用 SQLite 备份或停服完整保留；不能以复制活动单个 sqlite 文件冒充包含 WAL 的备份。本批未配置生产统计归档或迁移。

## P42/P44：期限和待执行记录基础

任务/请求读取及 inbox 队列项新增 `expires_at`，表示该修订的信封期限；任务还新增 `command_expires_at`，固定取 revision 1 的期限。后续状态事件可具有新的传输期限，不能据此延长原命令。两者是服务端队列项附加元数据，不改事件 1.0/1.1 信封 schema 或 body，主库 schema 仍为 2。

连接程序 runtimeSource 保留两个字段到持久投递来源。运行时日志验证 UTC 时间后原样保留。尚未接线的老服务/老来源可能没有该字段；将来调度器必须拒绝缺少可信原期限的执行，不得把新状态期限当原任务期限。现存 runtime_sources 重放若新增元数据产生冲突，当前按 fail-closed 保留并停止，应先对账，不能删除不确定 dispatch 或重发真实任务来迁就升级。

日志新增 `admit(...,event=...)`，把接收记录和对应运行时事件原子保存；`operations_in_state()` 按入库顺序取 admitted/claimed/unknown；`settle_unstarted()` 仅关闭从未领取的 admitted 工作，终态与事件原子提交，同结果重放保持 ACK，不让 claimed 工作自动变回可执行。

这批是调度器基础，**没有接成完整 Hermes 运行时**，不自动判定超时/取消，不发布未经观察的完成回执，不恢复原工具等待栈。原 ACP end_turn 仍不能作为任务完成证据。

证据：服务端真实重开/inbox 测试证明原期限保留；连接程序真实投递并持久化字段；日志 16 项回归通过，含双进程领取/领取后崩溃、原期限冲突、FIFO 重开、接收事务回滚、未领取终结和 ACK 重放；日志+工具合计 27 项与真实 MCP stdio 8 项兼容检查通过。查询工具 11 项通过。所有任务和答案为合成数据。
