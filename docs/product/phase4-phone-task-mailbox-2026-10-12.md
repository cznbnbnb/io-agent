# P43 手机任务收发组件与真机文件恢复

日期：2026-10-12；候选：0.1.49 / 10049；基线：d4a4304。

本批落实 P43/P44 的手机数据和传输层。正常任务页、任务凭据设置及手机→云端→真实 Hermes 模型的完整链路尚未交付，不能将这次组件或合成文件实验标为 AC-ASK、AC-VOICE 或正式 P43 验收通过。官方基础体验仍是独立交付底线。

## 修改及行为

- `TaskWire.ets`：沿用 P14/P40 的 task/request/answer/message/receipt 1.0 对象，校验稳定 ID、版本、完整 computer/agent/project/session 路由、选项、期限及存储回执。任务始终 `allow_create_session=false`，不悄悄创建替代会话。
- `TaskMailbox.ets`：按 owner/producer/server 分区；一个原子文件同时提交收件对象与游标，并保存命令/答案的原始序列化内容。处理短写、fsync、rename 和过时写入器；状态损坏时拒绝使用并保留原文件，不当作空队列覆盖。
- `TaskTransport.ets`：明确前台启用才发送；HTTPS、禁止重定向、响应大小/类型校验、有限超时。每次操作先用实际令牌核对 `/identity` 的三元身份、有效期及任务读取权限，再传递任务/答案。资料同步凭据不会自动成为任务凭据。
- `TaskMailboxLab.ets` 与隔离 Ability：独立合成文件实验，无有效网络目标、凭据、录音、眼镜连接或 Agent 执行。日常 App 业务入口未被重写。

命令在本地落盘后才可发送。重复同一个用户操作返回原始内容；同操作 ID 改正文返回冲突。稳定任务、事件和幂等 ID 从分区及操作 ID 派生，重启不会生成新命令。

发送开始前持久化 `sending`。中断、丢回复、非可信成功回复、429 或 5xx 后先查同一事件；只有经过鉴权的 `EVENT_NOT_FOUND/retryable=false` 才能允许原内容重发。期限届满且已确认不存在时保留过期记录，不自动延长期限或换新任务 ID。Retry-After 和退避写入账本。

服务器存储确认仅令发送行成为 `server_stored`。Agent 接收、原任务继续、任务完成、眼镜展示和用户回答仍是各自独立事实；结果消息也不自动变成任务完成。对象详情中的回执保留 subject_revision，不将旧版本的回执套到新版本。

## 回答、离线和取消

在线提交回答前读取当前问题及原任务详情，检查问题版本、有效期、选项、任务状态及完整路由，答案保留附加条件。缓存收件页不能单独授权回答：服务端收件页可能是历史 revision 搭配当前 head state，必须区分。

离线可把已知问题的答案保存为 `awaiting_refresh` 草稿，绑定原问题 ID/版本/任务/路由和原期限。恢复时重新读取经鉴权的当前详情；仍有效才发送原始答案内容。问题改版、关闭、已回答、任务关闭或过期，保留原内容并显示对应错误。明确不存在的问题只阻塞自己的草稿，不冻结无关命令。

服务端对首答执行原子竞争；手机不能在联网前承诺其答案已被接受。另一个终端先答时保留 `ANSWER_ALREADY_ACCEPTED`，通过原请求详情读回实际接受的答案。

取消准备同样实时读取任务并校验版本，只提交下一 revision 的 `cancel_requested`，不会本地宣称运行时已停止。服务端 revision 冲突需重新对账，不自动替换取消命令。当前协议需要 `tasks:update`，此权限范围比“仅允许手机取消”更广，任务凭据发放时必须明确其作用；本批未新签发或扩权任何生产凭据。

尚缺“从未发送的本地任务撤回”：未来只可在确定未尝试发送时本地终止；已发送或结果不明时必须对账并走服务器/运行时取消，不能伪装本地删除为已取消。
