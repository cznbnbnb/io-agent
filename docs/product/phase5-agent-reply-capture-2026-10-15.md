# P53 前置：独立语音回复收音

日期：2026-10-15。关联 P51/P53/P54、H07-I01。本文不改变 PRD 或正式验收出口。

## 场景与边界

0.1.75 已取得正常手机文字委托、真实公网、指定隔离 Hermes 原任务提问/完整条件回答/继续/结果及结清后冷恢复的证据，见 [P43 记录](./phase4-phone-task-connection-2026-10-15.md)。下一场景是眼镜询问后，用户明确同意才短时收音，完整条件最终回原请求。

当前先验证硬件前置：手机主动提交 business13/type2/rc1 后，原厂眼镜是否实际送回 type3 音频，以及停止和 type8 退出是否可靠。既有 `VoiceSession` 从固件唤醒进入普通问答模型，不能直接当原任务条件收音使用。本批独立组件只产生本机转写草稿，不调用问答模型、不产生任务答案、不新增日常资料。

两阶段建议卡、子卡 UID 到原请求/版本/会话的持久绑定和最终答案提交尚未接入。自检入口不是完成 P53 或 AC-ASK 的证据。正式 P43/P44 其余场景、官方基础对齐及 P25 朗读跟随保持开放。

## 最小实现

- `AgentReplyCapture` 属于 Ability 生命周期。页面只是观察者，不能因页面重建再开麦。启动需前台、原眼镜就绪、普通语音/录音/智记/提词/识别/通知均空闲；先准备现有本机 CTC Worker，再等旧普通助手发送队列排空。
- 在首次可能生效的开麦写入前，原子保存原眼镜和不透明 binding 的清理意图。只提交一次开启，写入结果不明时也只尝试停止。6 秒无音频则停止；自检最长 15 秒，组件限制 3–30 秒。重连和恢复不自动开麦。
- 复用固定摘要的中文流式模型与 `LocalFollowASR`，不下载另一套模型、不依赖云 ASR 密钥。按段 ID 替换局部识别，保留所有分句；不把附加条件概括成确认/拒绝。二进制音频只接受 protobuf field4，JSON-only 的 type3 作为异常停止。
- 新增 Worker `finish`：排在已提交 PCM 后，补 0.5 秒零输入，调用 SDK `inputFinished()`，有界排空解码，送回最后一段文字。0.5 秒是待真机验证的工程参数，不能以 SDK 存在该 API 推断音频已经完整收到。
- 停止先发 recorder(false) 及 type7/rc1，并等待识别封口和实际 Worker exit；还必须观察原眼镜的 type8。发送成功、线程退出、固件退出分别记录。缺任一确认则保留清理义务，禁止新收音，不把不完整文字恢复成可提交草稿。
- 前后台复用既有最长 10 秒系统清理窗口；不为实验申请持续后台录音。过期或拒绝后关链，保留未确认清理状态。普通业务的麦克风/显示/本机识别门禁均纳入此占用。
- 正常电脑任务设置中有明确标记的“语音回复收音自检”；不自动启用任务连接，不读取/复用已撤销测试令牌。转写只保存独立 `agent-reply-capture.json`，不改变原音、已有 ASR、资料修订、outbox 或文稿目录。

## 0.1.83候选：第二卡授权到原问题口述草稿

复用已验证的两阶段建议卡：第二卡真实选择同意后，先保存阶段、发匹配type35并移除原UID；等整个卡片发送链排空、共享卡片占用释放，才向`TaskVoiceReplySession`交接。重复type34不会再授权一次。开始前、联网重新核对后及实际串行开麦写入前，均核对同一原请求/修订、完整电脑/Agent/项目/会话、操作ID、期限、当前配置、原眼镜及前台状态。

每次收音使用新的随机attempt ID，与完整原绑定和眼镜身份一起写入既有收音日志；不截断原绑定。默认15秒，重连、冷恢复、旧卡动作和CLI均不能自行重新开麦。有效完整文字只在原绑定仍可回答时原子保存到原问题的`review`草稿，之后才清理收音副本；保存失败保留原始完整文字。取消某次口述不取消电脑任务，新旧attempt互不停止或归并。

原问题已过期或保存失败时，正常页可显示/复制尚未交给Agent的保留文字，再明确丢弃；已复制成功但副本清理失败可以重试。撤回原本地草稿后，未处理的收音文字会阻止新问题覆盖其绑定，清理入口继续可见；空文本失败不会无故阻塞下一问题。数据不可读和退出未确认时保持保护门禁。

停止不再先封口ASR再丢掉蓝牙尾包：正常停止期间继续接收最多4秒/128000字节PCM，停止命令链结束并观察到原眼镜有效退出事件后才封口、等Worker实际退出。超时、字节超限、封口后仍有音频或取消时仅保留片段，不标为完整答案；迟到退出只可解除清理义务，不把已超时片段追认为有效。取消重入、挂起写入、同步断连及旧generation均不能使下一轮早关或错误发布。这里4秒是工程接收上限，不是已经通过PRD延迟指标。

### 原厂退出和音源的实际参考用法

本地官方Android 1.0.0/52反编译原件的实际函数体已核对，关键原件SHA及调用位置见[静态证据](../../rebuild/phase1/assistant-stop083-static-2026-10-15.json)。这只是对应App版本的静态参考，未证明当前眼镜固件所有行为。

- `AssistantSessionManager.stopAssistantInternal`在停止workflow后不等待回报地发送business13/type7/rc1，随即清理本地音频入口/路由并结束运行状态。`GlassMessageHelper`将独立收到的type8解释为退出原因事件，没有请求UID或type7关联等待器。没有证明“发送type7必须收到type8 ACK”；无type8不能单独认定命令失败。
- type8的rc1在该枚举中是录像打断，rc3为摘下，rc6为双击退出，rc7为skill退出；不能把type7/rc1和type8/rc1当成相同“正常退出确认”。本候选记录实际退出原因，`device_event`仅表示观察到退出事件，仍不等于任务成功。
- 此处13是business ID；内层type3承载protobuf音频data，内层type13是技能结果。原厂type2开/关只发rc，没有可用的mic/channel选择字段；真实助手输入配置为Opus/16kHz，但这不证明骨传导、左右声道或佩戴门控。当前固件原始二进制/驱动函数体未找到，本轮近静音原因保持未知。

因此保守退出门禁是本候选的工程约束，不能写成已证实的原厂ACK协议。下一硬件出口要对照正常助手停止时的实际音频/退出事件和镜片；若镜片退出但无type8，只记录这一事实，再设计有证据的结束边界，不用假回执或静默清除占用。完整日常语音产品尚未通过。

旧0.1.76的245包/3非零只留有当时UI计数，没有保存该轮逐包压缩payload，无法重算长度、重复帧或Opus静音标记。私有证据中的`before/after-audio.bin`都是升级保护用的既有53207字节Ogg原音（SHA256 `cd2ba1e3a85dfb445fed45ec8bf5c0d29acd261a579349c9bcedc5462e0477e1`），不是本次助手音频。0.1.71外放有声WAV及提词RMS属于另一路实验，也不能替代0.1.76采音流。当前CLI统计用于下一轮实际观察，不追造旧原始数据或据统计猜物理麦克风。
