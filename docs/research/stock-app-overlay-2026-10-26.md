# 原厂正常更新与独立 Agent 悬浮窗：可行性边界

2026-10-26；仅调查，不改变当前 APK、权限或部署。用户已澄清 Tailscale/ADB 仅开发调试；音频和转写只供 App 内导出，不建设 Agent 从手机取文件的服务。

## 结论

可以做独立安装、独立更新的 Agent 悬浮窗，并与原厂 App 共存。但把当前功能全部搬到悬浮窗，不能自然获得原厂账号、智记或眼镜通道。悬浮窗只是显示入口，不会获得原厂进程和私有数据的访问权。

当前版本基于原厂 1.0.7 /230 重建，用项目自有签名安装。Android 更新必须满足相同应用 ID，签名相同或具有有效的签名轮换证明；我们没有原厂私钥。因此现装包不能直接接受原厂签名的覆盖更新。改成独立应用后，原厂包可以正常更新，但需要重新设计两者之间的数据接口。[Android 更新规则](https://developer.android.com/google/play/app-updates)。

## 当前功能的依赖

| 功能 | 当前实现依赖 | 独立应用的可行入口 |
|---|---|---|
| Agent 任务、连接、默认会话 | 自有服务器与自有 UI | 可独立迁移，账号迁移需单独设计 |
| 悬浮入口 | 当前 Activity 内的入口与 Dialog | 独立应用申请悬浮窗权限，显示自己的界面 |
| 智记列表、AI 总结、删除 | 原厂登录状态、私有缓存、签名请求 | 原厂正式开放的 API/授权，或明确导出分享 |
| 原音保存和导出 | 原厂蓝牙回调、当前进程内原音封存 | 原厂开放音频接口，或独立 SDK 与配对方案 |
| 眼镜提词器、录音、确认卡 | 原厂 SDK 和进程内协调/钩子 | 原厂公开 SDK/服务接口；需验证与原厂同时连接 |

代码依据：`Host107Login` 从宿主登录状态取账号；`Host107LifelogHttp` 调用宿主 `CloudDictResApi.genSign` 并使用原账号令牌；`OfficialHiveCache` 和本机音频归档读取宿主数据；当前构建保留原厂 DEX 并加入明确包装和附加 DEX。这些是代码核对，不代表已测试独立应用方案。

Android 默认按 UID 隔离应用数据和进程；拿到悬浮窗权限不会解除沙箱。[应用沙箱](https://source.android.com/docs/security/app-sandbox)、[SYSTEM_ALERT_WINDOW](https://developer.android.com/reference/android/Manifest.permission#SYSTEM_ALERT_WINDOW)。

## 后续推荐

优先调查原厂是否提供可授权的 SDK、账号及智记开放接口。若接口齐全，可拆成独立 Agent App；若没有，短期仍需跟随原厂新版本重新适配、审计和签名。Root/Hook/虚拟容器会增加安装门槛和版本耦合，不能当作“随原厂更新自动兼容”的保证，本轮不实施。

本次未卸载原厂数据、未换包名、未修改签名、未安装外挂或申请额外权限。
