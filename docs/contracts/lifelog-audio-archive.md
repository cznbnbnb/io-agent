## dev80 本地原音保存与导出实现

正常进程现在将已有 AssistantMsg 原包写入账号隔离的耐久收集器，原厂收包方法仍执行一次。回调仅复制有界内存；账号读取放在后台，主线程只观察当前连接和原厂配置。准入要求唯一已认证设备、连接代际、同账号的 taskId/dialogId、Opus/16 kHz 配置，以及原消息中的相同 taskId；失效、过期上下文或队列超限停止本地保存，不控制原厂录音。

每个本地会话先保存来源记录，再接收完整原包。原始消息与数据保留；A3 分帧或解码失败不删除原件。资料来源尚未出现时保持待关联，只有同账号 conversation ID 精确匹配才允许导出。dev80 同时接收原厂当日读取、本机资料库及自动增量读取返回的来源，避免仅依赖 Flutter Hive 缓存更新。App 重启后恢复已刷盘批次，并把未结束的会话标成中断，不能延续显示成完整录音。

dev81 把写入保护改为读取上下文监视器已核验的快照。监视器仍在原生快照前后分别读取账号，账号、设备、连接代际、任务、epoch 与 3 秒时效均保留；失败仍停止保存。日志恢复会对已有批次逐一调用保护，旧写法每次都等待原厂安全存储，日志增长后可能使自己的时效检查超时。但 dev81 真机仍出现同一任务的快照过期失败，不能称已修复；[失败证据](../../rebuild/android-app/r4-audio-writer-dev81-2026-10-24.json)保留。

dev82 在写入线程或调度线程发现快照过期时，合并请求一次完整监视器刷新，最多等待 4 秒；等待期间不写入。只有账号/原生上下文/账号再次核验通过、身份和 epoch 未变化、最新快照不超过 3 秒，才继续写入；刷新超时、中断、不可用或真实变化仍拒绝。正常定时轮询与主动刷新共用一次在途请求，避免启动多条轮询链。新写法不逐批同步读取安全存储，也不延长快照时效；实际读取不可用和已证账号变化分别报错。运行时自测用真实增长日志复现旧失败，并覆盖并发过期请求合并、刷新后恢复、换账号时拒绝写盘和 4 秒超时。限频健康日志仅包含计数、阶段及错误码，不包含账号、任务 ID、正文或音频；无法核验而未接纳的输入另计 `input_unverified`，不冒充已保存。

dev83 补上到达时快照已过期的原包缓冲。只对已知设备和已有绑定复制原包，保留原先账号、设备、代际、任务、epoch、接收时间和 FIFO 顺序；SDK 回调只排队并请求刷新，不等待账号 IO。待核验原包只有 10 秒核验窗口，消费前仍须通过上述完整刷新及新鲜度核验，并再次匹配原消息 taskId；失效、身份变化、超时或容量阻断时清零，不落盘。原包内存上限 32 批/2 MiB，包含已经出队但仍在等待核验的一批。`input_deferred` 计延后核验输入，`input_revalidated` 仅计重新核验后进入收集器队列的批次，仍不是耐久保存回执；丢弃与持久保存分别看 `input_unverified`、`input_dropped` 和 `saved_batches`。本机测试覆盖原始字节/时间戳不变、有序落盘、六类绑定边界拒绝、核验窗口过期、在途容量及清零，并验证旧的“过期即丢弃”写法不能通过同一测试。

导出通过收集器的有序检查点冻结已收到的前缀，后续音频继续写新段。解码和导出在另一条工作线程进行，不占写入线程。每段先校验原始日志，再由私有原厂 Opus 解码器逐包核对，原包不重编码；按照 [RFC 7845](https://www.rfc-editor.org/rfc/rfc7845.html) 和 [RFC 3533](https://www.rfc-editor.org/rfc/rfc3533.html) 加上 Ogg 容器。当前支持单声道 A3；A4 不冒充已确认的可播放内容。导出 ZIP 包含各音频片段、接收范围索引和不完整性说明，不伪造缺段时长或补静音。手机系统文件选择器允许保存到用户选择的位置，完整文件先校验 SHA，再流式写出，并持续核对账号。

派生导出缓存最多两份，每份 512 MiB、保留一小时供系统选择器恢复；取消/完成后清理，过期缓存下次导出时回收。它与原始音频保留策略独立，清理不会碰原件。资料页显示“部分原音”“等待关联”“曾发生中断”等实际状态，不将文字同步回执当成原音备份。

源码自测覆盖延迟关联、跨账号隔离、有序冻结后继续保存、原件不变、损坏/过期拒绝及 ZIP/Opus 输出；独立 FFmpeg 已解码合成导出。dev80 最新原厂来源出现后已精确关联，真实 ZIP/Ogg 导出及正常系统选择器保存到手机通过；旧待关联和中断失败仍保留。[真实导出证据](../../rebuild/android-app/r4-audio-export-dev80-2026-10-24.json)。dev82 的后台被动观察结果见[本批证据](../../rebuild/android-app/r4-audio-writer-dev82-2026-10-24.json)；短观察不证明全天连续无丢失，听感仍未人工验收。远程 72 小时保存/到期尚未发布和接入手机，原厂权威删除仍开放，当前仅文字上传授权不扩大。

dev83 已安装且元数据探针通过；本轮正常进程的独立原厂观察器没有原包，不能将安装或源码检查当成真实缓冲验证。[dev83 证据](../../rebuild/android-app/r4-audio-input-dev83-2026-10-24.json)。已有数据自然恢复后由开发者补验，不为验收自动启动新录音。

## 服务端原音归档 v1（源码已验证，尚未发布）

`audio_archive_v1` 是独立能力；新接口要求 `audio:write` 或 `audio:read`，文字写入/读取和一次配对角色不自动拥有原音权限。现有正式凭据仍仅文字。原音文件按当前 owner 下的资料 ID、已存修订及原正文摘要绑定；存储回执只证明完整字节已校验落库，`recording_completeness_verified=false`，不证明原厂录音完整或编码可播放。

- `POST /v1/audio-uploads`：`{material_id,material_revision,kind,media_type,bytes,sha256,capture}`；`capture` 含 `first_received_at,last_received_at,recording_complete`（客户端声明）。`raw` 对应 `application/vnd.turboio.lifelog-archive`，`playable` 对应 `audio/ogg`，两种原件/派生文件分别校验。相同 owner、资料、kind、完整 SHA 生成固定 object ID；已提交对象不能换一个发送键重新延长保留期，已存在对象的来源修订和元数据也不能改写。
- `GET /v1/audio-uploads/<id>` 返回已收分块与暂存截止；`POST .../parts/<index>` 接收 `{data,sha256}`（标准 Base64）。每块 128 KiB，最后一块按实际大小；不符字节数/摘要、改写分块、跨 producer 续传均拒绝。暂存 24 小时，未完成对象不产生远程保存回执，过期后清空块并允许同原始意图重新上传。
- `POST .../finalize` 请求为 `{}`；在固定顺序锁下逐块核对，再流式计算完整 SHA。只有事务成功才发布 `storage_verified=true`、固定 `stored_at` 和 `expires_at=stored_at+72h`。丢提交回复、进程重启与重试返回原存储时间，不续期。
- `GET /v1/audio/<id>` 取元数据；加 `?index=N` 分块读取，每块带整体/分块摘要及到期时间，客户端全部校验后再发布导出文件。每次重新核对凭据、owner、资料未删除和原音未到期；不返回过期音频。`GET /v1/material-audio/<material_id>?limit=50&after=<id>` 按固定 ID 分页，返回 `next_after`；过期条目只保留元数据。

载荷位于单独 `<文字库>.audio.sqlite`，绑定同一 server ID，不进入文字库 `backupTo`。侧库使用 FULL 同步、DELETE journal 和 secure_delete；到期后清除音频块、保留去重/到期元数据。正常服务启动和每 60 秒清理，读取拒绝在到期瞬间生效；服务停机期间需恢复运行后清理，不承诺文件系统快照或磁盘取证擦除。侧库不可用时原音接口 503、能力不发布，文字与问答仍正常。旧服务代码回退没有新清理器，因此原音正式发布还需独立的回退/到期演练；旧文字发布 profile 已拒绝带原音依赖的源码，不能遗漏模块直接上线。

默认单对象最多 512 MiB；每 owner 活跃预留最多 128 份/2 GiB，全服务 8192 份/10 GiB。满额拒绝新上传，保留已收对象。SQLite 同步操作仍可能阻塞小服务，真实大文件负载尚未验收。原厂权威删除发现与手机原音上传队列尚未接入；缺少来源头只拒绝读取，不据此销毁未到期原音；服务器收到资料墓碑后立即拒绝相关音频的读取/迟到提交，并在清理轮次移除载荷，此合成行为不能当成已完成原厂删除同步。

已用 Node 22.23.2、真实临时 SQLite、HTTP 和独立进程检查续传、提交前/后退出、三天边界、到期块清除、文字备份隔离、撤销、分页及侧库故障隔离。真实服务默认一分钟定时器清理通过；只用合成字节，尚未部署、签发真人原音权限或上传手机原音。

## Android 原音传输与耐久队列（源码通过，尚未接运行时）

连接格式为 `turboio-audio-sync/1`，与文字导入分开；只复用目标 URL/owner/producer/server 的语法和绑定，不复用文字授权。每次网络轮次先核验新鲜 identity、有效期限、精确目标、`audio:write` 和 `audio_archive_v1`。传输层仅 TLS、固定原音路由、禁止重定向、有限超时和有界 JSON。原音配置的独立 Keystore 封装/导入及实际 TLS 联调尚未实现。

`AudioUploadOutbox` 在 `lifelog-audio-uploads` 持全局锁，账号与远程目标分别绑定；元数据不保存 token。默认所有账号合计 512 MiB 暂存、512 个历史队列项，至少保留 64 MiB 磁盘余量；满额停止新增，不清理旧原件。来源必须是内部生产者发布的 `lifelog-audio-payloads/<account-sha256>/<payload-sha256>/payload.bin`，拒绝任意文件和符号链接。该可信来源生产者尚未接入，因此目录限制本身不证明内容是智记原音；生产者仍须证明封存、同账号/设备/来源和文字已存修订正文摘要。

复制前先保存准备意图；有界流式拷贝并核对整件/每块 SHA，刷盘、原子改名、同步目录后才发布待传状态。准备中断可从不可变来源重做，完整改名但未发布可重新验证后接回。每轮先持久化发送意图，服务器固定对象 ID 对账后只补一个缺块或提交；分块/最终回执丢失及进程中断均按服务器事实恢复。每次请求前后必须通过调用方账号/启用状态/代际守卫；未来运行时不能省略。HTTP401/403 转为明确授权阻断，新同目标显式授权通过预检后可继续。

回执精确校验 owner、producer、对象、原资料修订/正文摘要、完整载荷、保存及到期；仅存储成功可发布固定 72 小时回执。回执先耐久保存，再删除本队列拥有的上传副本；中途清理失败不丢回执，后续进程只重试本副本清理，不删除来源快照、原厂文件或用户导出。坏回执/文件变化保持阻断和本地文件；手动重试仍须重新预检/校验。重复对账不续期，显示基于回执到期时间，历史存储回执与“当前远程仍保留”分开。客户端允许协议内的生产者完整性声明，但服务器的 `recording_completeness_verified` 必须为 false；当前真实来源还不能声明全天完整。

真实临时 HTTP/SQLite、独立 JVM 四处强制退出恢复和 Android 编译/D8 通过，限合成不透明字节；不是产品手机上传或实际 TLS 测试。手机仍 dev83；来源生产者、自动调度、配置/UI、服务专用发布/回退、真实原音授权及权威删除尚未接通。[可复核证据](../../rebuild/android-app/r4-audio-client-2026-10-24.json)。

后台来源发现用收集器 `catalog()` 的有序只读屏障：在同一 writer 队列等待此前批次，返回同账号管理目录的深拷贝；不调用 `end`、不分配新段或更改原件回执。它和人工导出的封存 checkpoint 共用一个在途额度，停止后不接新屏障；交付前重新核对准入，异常完成 future。自动生产器只能选其中已封存且来源已核验的段，不能读正在增长的原件，也不能把目录项当上传授权。组件真实文件测试 640 次轮询不封段，原件/状态/管理回执逐字节保持；封存型错误变体被同一回归检出，既有导出仍通过。此接口尚未进入 dev83 或自动运行时。[目录屏障证据](../../rebuild/android-app/r4-audio-catalog-2026-10-24.json)。

### 可验证原件快照生产器（合成端到端通过，未接手机）

`LifelogAudioPayloads.TextSource.stored` 直接读取绑定同一 base/owner/producer/server 的文字 outbox，最新修订须有有效已存回执并为 lifelog/upsert；不能用未上传的新修订或任意传入正文冒充服务器来源。源段必须同账号、已封存、无未知尾部，peer/generation/clock、原消息 task 与已核验会话/material ID 精确一致。原件 reader 流式提供原始 journal 字节和校验链，不重新编码元数据、不忽略不支持批次。当前原音快照只支持固定已知字段 A3；未知 protobuf/JSON 字段及 A4/A5 保留本地并明确拒绝准备，待各自来源/格式适配，不将其省略后声称完整。

原始封套为 8 字节 ASCII `IOARAW01`、大端 uint32 元数据长度、大端 uint64 journal 长度、最多 65536 字节规范 UTF-8 JSON、完整 original.frames。JSON 含原件状态/归属/链、接收上下文和精确来源说明，不含 bearer、文字正文或文字修订；`recording_complete=false`，封存不是物理完整性证明。外部 manifest 单独绑定已存文字修订和正文摘要。同一原件对应固定载荷 SHA；后续文字修订可以复用队列已有对象，固定第一份 manifest/body SHA/存储时间/72 小时期限，不能自动重包装续期。

## 原厂入口与已验证格式

固定宿主 1.0.7 的 A3 实时帧经 `com.rayneo.rayneo_venus_sdk_plugin.e.h(message,data)` 解析，进入 `t8/b$b.c`；A4 缓存数据经 `t8/b$b.a` 写入 `files/always_on_cached_audio/<resolvedTaskId>.opus`，结束后通知 `taskId/filePath/sizeBytes`。A3 的实时数据与 A4 的缓存结束不能互相替代。后缀 `.opus` 本身不证明编码或可播放封装。

`AlwaysOnAudioBatch` 已按原厂解析器完成手机合成对照：87 组输入、331 帧、2825 个检查一致；另有 1362 项 JVM 检查。没有使用真人音频、启动采音或播放。

- JSON 出现 `mode/frameCount/vpuMask/vadMask` 任意字段，即进入新分帧路径；字段值为 null 仍决定路径。
- 新路径按 240 字节切帧，最多 31 帧；帧数取可用完整帧数、声明值和 31 的最小值，并下限为零。没有声明值时使用可用帧数。
- `vpuMask/vadMask` 的第 i 位对应本批第 i 帧。两字段均存在时才标记 flagsPresent；单个缺失时仍保留另一个字段提供的位值。
- 旧路径把整批数据视为一帧，mode=0、index=0、count=1，`vpu/vad` 的整数 1 表示 true。两字段均存在才标记 flagsPresent。
- 新路径声明值被收缩或尾部不足 240 字节时，归档必须保留整批原始字节，并记录 `clamped/unparsedBytes`；不能因为原厂 ASR 忽略尾部就丢弃原件。

本机适配器比原厂 JSON 数字自动转换更严格：只接收整数/null，未知字段、重复键、字符串数字、非法任务 ID 或超限均明确拒绝解析。归档调用方须先保存有界原始输入，再解析；解析失败保留原件与错误。此处描述早期分帧器阶段；dev80 已按上述规则接入被动保存，原件先入库，导出时才解析。

## 来源与完整性要求

每批帧的 index 从零重启，它只表示批内位置，无法证明跨批无丢失、顺序连续或未重复。不得据此拼出“完整录音”。taskId 也可能由原厂回退为最近值或生成值，不能直接认定其等于 conversation sourceId。

A4 结束回调只说明该原厂缓存文件结束，仍须校验文件稳定性、实际字节数/哈希、账号、设备、taskId 来源及对应智记。手机当前没有该缓存目录；仅文件名相同的四个 Opus 候选均为普通录音来源，不当作全天对话原音。详见[来源调查](../../rebuild/android-app/r4-audio-source-audit-2026-10-24.json)。

## 耐久原件日志（组件及早期验证）

`LifelogAudioArchive` 在独立账号/stream 目录保存原件。账号绑定、设备摘要、连接代际和 stream ID 构成固定归属；每批接收带本机递增序号、原消息、A3/A4/A5/断连类型、墙钟时间、单调时间及其进程时钟标识。这里的序号是本机写入顺序，不是眼镜端无丢帧证明。

## 归档管理器（组件及早期验证）

`LifelogAudioManager` 持有跨账号的全局写锁。默认原件日志总量 512 MiB、每段 8 MiB，最多管理 256 段；单段硬上限仍为日志组件的 256 MiB。容量统计包括其他账号、未知和隔离日志的原件字节，不读取其他账号的音频内容。小型索引与回执文件另有目录数/文件长度上限。写入前还需至少保留 64 MiB 可用磁盘空间；空间不足或段数耗尽时明确拒绝，不覆盖旧数据、不自动删除。

分配新段前先保存归属和分配意图。轮转先冻结旧段为 segment_boundary，再分配新段；原始接收序号以账号、设备代际及进程时钟标识为范围跨段递增。相同接收序号的重试须核对整批原消息、原字节、种类和两种时间；相同内容的不同序号仍是不同接收事件，不按音频字节去重，避免删掉静音或重复语音。

原件回执与管理索引之间中断时，重新从日志核对已存记录并追平索引。半截/损坏/无归属段保留并进入 needs_attention；新段可继续，但不隐藏旧段的异常。新进程时钟接管同账号的遗留开段时，明确冻结为 process_interrupted；其原件与异常提示跨重启保留。其他账号不做来源恢复，也不能通过目录或 stream ID 读取内容。

提供同账号历史段目录与冻结段校验读取。读取先完整核对日志，再逐批核对摘要、顺序和接收回执，守卫在交付前后检查；消费者先写暂存输出，只有读取整体成功后才可发布派生文件。这里的冻结、接收顺序与哈希都不证明眼镜端无丢帧、物理录音已完成或智记来源已对应。
