# 智记原音归档接入（开发中）

R4 原音目标：关联当前账号的真实智记来源，完整原音持久存入服务器后固定保留 72 小时，显示到期时间并可导出到手机。到期不删除文字或已导出的手机文件。当前正式凭据只授权文字；原音上传还未接通。

## 原厂入口与已验证格式

固定宿主 1.0.7 的 A3 实时帧经 `com.rayneo.rayneo_venus_sdk_plugin.e.h(message,data)` 解析，进入 `t8/b$b.c`；A4 缓存数据经 `t8/b$b.a` 写入 `files/always_on_cached_audio/<resolvedTaskId>.opus`，结束后通知 `taskId/filePath/sizeBytes`。A3 的实时数据与 A4 的缓存结束不能互相替代。后缀 `.opus` 本身不证明编码或可播放封装。

`AlwaysOnAudioBatch` 已按原厂解析器完成手机合成对照：87 组输入、331 帧、2825 个检查一致；另有 1362 项 JVM 检查。没有使用真人音频、启动采音或播放。

- JSON 出现 `mode/frameCount/vpuMask/vadMask` 任意字段，即进入新分帧路径；字段值为 null 仍决定路径。
- 新路径按 240 字节切帧，最多 31 帧；帧数取可用完整帧数、声明值和 31 的最小值，并下限为零。没有声明值时使用可用帧数。
- `vpuMask/vadMask` 的第 i 位对应本批第 i 帧。两字段均存在时才标记 flagsPresent；单个缺失时仍保留另一个字段提供的位值。
- 旧路径把整批数据视为一帧，mode=0、index=0、count=1，`vpu/vad` 的整数 1 表示 true。两字段均存在才标记 flagsPresent。
- 新路径声明值被收缩或尾部不足 240 字节时，归档必须保留整批原始字节，并记录 `clamped/unparsedBytes`；不能因为原厂 ASR 忽略尾部就丢弃原件。

本机适配器比原厂 JSON 数字自动转换更严格：只接收整数/null，未知字段、重复键、字符串数字、非法任务 ID 或超限均明确拒绝解析。归档调用方须先保存有界原始输入，再解析；解析失败保留原件与错误。当前该归档调用方尚未接入产品。

## 来源与完整性要求

每批帧的 index 从零重启，它只表示批内位置，无法证明跨批无丢失、顺序连续或未重复。不得据此拼出“完整录音”。taskId 也可能由原厂回退为最近值或生成值，不能直接认定其等于 conversation sourceId。

后续归档记录须包含：当前账号绑定、设备/连接代际、原消息提供的 taskId 与是否回退、单调接收序号和时间、原消息与原字节的摘要、批内字段、未解析数据、结束证据及来源对应证据。原始帧与解码后的可播放文件分别保存并校验。当前正式资料凭据只覆盖文字；先准备代码与合成验证，真实上传前落实原音权限和真机前置。

A4 结束回调只说明该原厂缓存文件结束，仍须校验文件稳定性、实际字节数/哈希、账号、设备、taskId 来源及对应智记。手机当前没有该缓存目录；仅文件名相同的四个 Opus 候选均为普通录音来源，不当作全天对话原音。详见[来源调查](../../rebuild/android-app/r4-audio-source-audit-2026-10-24.json)。

## 原厂会话链路的进一步核对

固定 1.0.7 的 `o8.m.p` 会规范化配置，将 taskId 同时写入 dialogId；未指定正采样率时补 16000，空 channelRole 补 guest=0。正常路径默认 Opus，mock 路径可取 PCM 或指定格式。这些是配置规则，不是当前收到的数据已证明为某种编码、声道或可播放封装。

A4 原件写入前经 `o8.m.v` 解析 ID：显式值、当前会话 z、最近会话 B、自动生成值依次回退。`onAlwaysOnResponse` 向 Flutter 转发当前 taskId 与独立 roundId、finished、text；`onCachedAudioReady` 转发 taskId、filePath、sizeBytes。两回调都没有直接给出官方 conversation sourceId 的证明，必须继续与当前账号来源核对，不能按文件名、标题或时间接近猜配。

本批对话缓存调查使用独立 OfficialAudioMetadataCache，不扩展其他诊断的路径假设；只输出字段形状、计数与 ID 匹配。当前固定官方主机的账号缓存中，68→69 个来源仍无 A4 缓存目录；正常打开一条历史智记及其原始记录后也没有缓存 conversation/query 响应。这不证明原厂没有相应服务，只证明当前所查缓存无法提供关联证据。

原厂当前上下文的只读字段观察在诊断轮次中得到 0 个监听器，未获取配置；诊断进程的启动边界不能代表正常 App 的持续状态。下一步须在正常运行中常驻被动观察已存在的音频流，并取得实际原包/配置与来源对应。不能为了补证据自动发起新录音，也不重复扫描同一批缓存当作进展。

## 耐久原件日志（源码已实现，未接采集）

`LifelogAudioArchive` 在独立账号/stream 目录保存原件。账号绑定、设备摘要、连接代际和 stream ID 构成固定归属；每批接收带本机递增序号、原消息、A3/A4/A5/断连类型、墙钟时间、单调时间及其进程时钟标识。这里的序号是本机写入顺序，不是眼镜端无丢帧证明。

原始日志使用长度前缀、JSON 元数据、完整二进制和 SHA-256 尾摘要；元数据包含前一条链摘要，初始摘要绑定归属。每批原件刷盘后，再原子发布状态回执，并同步目录。恢复会重新校验已确认前缀：完整可校验的未回执记录可以恢复，同序号且内容、时间和元数据完全相同的重试不重复追加。没有回执不等于没有保存。

半截记录、非法长度或校验冲突的尾部原样保留，禁止继续追加；已确认前缀损坏时拒绝打开且不覆盖原状态。不截断、补造字节或自动删除尾部。调用方应保留该日志并开始新的明确中断段，后续再做受控对账。独立写锁、路径/符号链接检查与每次操作的账号守卫仍须通过。

单日志上限 256 MiB、131072 条；一条原消息最多 16 KiB、原字节最多 64 KiB，用于保留完整 AssistantMsg 原包；A3 分帧器输入仍限制 16 KiB。管理器已提供总容量与段切换，本机清理和真实入口仍未接通，所以不能单独开启全天采集。`seal` 只冻结原件日志，`recording_complete/source_link_verified` 始终为 false；后续完整性和来源证明须单独绑定已冻结原件摘要，不能反过来改写原件。

验证：Mac 实际文件系统 93 项及独立 JVM 在原件 fsync 后直接 halt(17)、另一进程恢复去重通过；Android 目标进程独立合成目录中同样 93 项通过并清理。首次使用驱动包 cache 创建目录失败，改用目标进程独立 cache 后通过；失败保留。没有采集、读取真人音频、播放或上传。该验证不等于真实手机掉电、实际录音或八小时稳定性通过。

## 归档管理器（源码已实现，未接采集）

`LifelogAudioManager` 持有跨账号的全局写锁。默认原件日志总量 512 MiB、每段 8 MiB，最多管理 256 段；单段硬上限仍为日志组件的 256 MiB。容量统计包括其他账号、未知和隔离日志的原件字节，不读取其他账号的音频内容。小型索引与回执文件另有目录数/文件长度上限。写入前还需至少保留 64 MiB 可用磁盘空间；空间不足或段数耗尽时明确拒绝，不覆盖旧数据、不自动删除。

分配新段前先保存归属和分配意图。轮转先冻结旧段为 segment_boundary，再分配新段；原始接收序号以账号、设备代际及进程时钟标识为范围跨段递增。相同接收序号的重试须核对整批原消息、原字节、种类和两种时间；相同内容的不同序号仍是不同接收事件，不按音频字节去重，避免删掉静音或重复语音。

原件回执与管理索引之间中断时，重新从日志核对已存记录并追平索引。半截/损坏/无归属段保留并进入 needs_attention；新段可继续，但不隐藏旧段的异常。新进程时钟接管同账号的遗留开段时，明确冻结为 process_interrupted；其原件与异常提示跨重启保留。其他账号不做来源恢复，也不能通过目录或 stream ID 读取内容。

提供同账号历史段目录与冻结段校验读取。读取先完整核对日志，再逐批核对摘要、顺序和接收回执，守卫在交付前后检查；消费者先写暂存输出，只有读取整体成功后才可发布派生文件。这里的冻结、接收顺序与哈希都不证明眼镜端无丢帧、物理录音已完成或智记来源已对应。

Mac 69 项管理器检查以及三个独立进程中断/恢复点通过；Android 同样 69 项通过，原件日志的 93 项回归通过。安卓 Files.getFileStore 查询空间曾抛 SecurityException，改为 File.getUsableSpace 后真机通过，保留失败记录。当前管理器已由下述有界被动收集器调用；尚未接真实入口、产品状态界面、解码器或服务端上传。

## 有界被动收集器与健康记录（源码已实现，未接原厂回调）

`LifelogAudioCollector.open` 在 I/O 线程打开管理器和账号健康文档，先持久化未完成标记，再返回可附加的观察者。`offer` 只核对缓存的账号/设备代际准入令牌、校验有界输入并复制到内存；不得在 Admission 中读取磁盘、SDK、凭据或网络。不同设备/代际忽略。默认最多 64 批（含正在写入批）和 2 MiB 计费内存；配置硬上限 128 批/4 MiB。原包 64 KiB、消息 16 KiB，超过限制不截断。

QUEUED 仅表示进入内存，只有后台追加原件和回执成功才计 saved。溢出或输入不合法停止接收，记录一次明确拒绝，已接前缀继续排空；写入异常或准入失效时，其余已接批计 unconfirmed，不能断言丢失，因为原件可能已经刷盘。停止异步排空、冻结、关闭，再保存终态；健康记录尚未结束时仍显示 DRAINING，不能提前报告停止完成。所有状态继续明确 recording_complete/source_link_verified=false。

`LifelogAudioHealth` 使用独立账号文档，最多 32 个账号、96 个文件，每文件 64 KiB。仅保存归属和计数/错误码；不含音频或转写。进程意外结束留下未完成标记，下次同账号启动累计 interrupted_runs，不虚构内存尾部丢失数量。历史拒绝、未确认批和错误跨正常重启保留。产品 UI 尚未接入，读取状态仍须核对当前账号。

验证：Mac 收集器 48 项、日志 93 项、管理器 69 项；独立 JVM 在批次尚未完成时 halt(27)，新进程检测到未完成标记。Android 同样 48＋93＋69 项通过并清理合成目录。驱动首次安装被系统取消，正常收起覆盖层后重试成功；未修改系统权限或安装产品新包。当前原厂回调尚未接入，没有采集、读取或上传真人原音。

## 正常进程的被动观察入口（dev78）

固定宿主 `e.c(peer, AssistantMsg)` 增加旁路：只做至多 64 KiB 的内存复制，原方法随后执行一次，观察器异常不拦截原厂处理。没有替换原厂解析器、监听列表、SDK 会话或录音控制。原厂整个类可重建至此前固定 SHA，新增包装单独审计；宿主显式包装总数为 9。

`AlwaysOnWire` 只为诊断读取 version/type/message/data 与有界未知字段；重复已知字段、未知组、非法 UTF-8、越界或歧义明确计解析失败，但原始输入仍交给原厂。`LifelogAudioObservationRuntime` 在正常页面/无页面启动时初始化，32 批（包括在处理批）、2 MiB 队列；超限计 dropped，不阻塞原厂。后台汇总 A1/A3/A4/A5、批数、长度、taskId/peer 哈希、已观察账号及缓存精确匹配，至多保留 24 种样本。A3 记录分帧边界与首字节分布，不能据此认定编解码成功。

观察器只读取原厂已打开账号和缓存；账号/原厂配置观察有单独时间，可能晚于原包到达，所有记录均明确 account_origin_verified/source_link_verified=false。它不把异步缓存命中当作会话归属证明，不保存原文、音频或明文 ID，不调用 HTTP、SDK 起停、解码器或播放器。独立固定元数据文件 `lifelog-audio-observation.json` 每 30 秒至多保存一次，原音归档和上传仍未启用。
