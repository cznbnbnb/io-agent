# Android 智记自动同步

2026-10-24 源码与合成验证；尚未装机。正式资料凭据未续签。

## 调度与范围

沿用资料同步的明确开关及已登记账号/服务器。关闭、凭据过期、未登录或账号不符时不读原厂、不上传，也不自动签发凭据。正文读取页面独立工作，不以允许上传作为查看本机智记的前提。

进程启动后恢复调度，正常每分钟检查一次，串行执行。每轮读取今天和一个补查日期：首次是昨天；中断后从已完成日期继续逐日补查。首次启用之前的更早历史仍由用户按日期/月选择。成功轮次才推进补查日期，空列表只说明本轮未取得正文，不会生成删除。

调度写盘后才开始网络工作，进程重启不会绕过间隔。失败按 1、2、4、8、15 分钟退避；系统网络恢复通知可提前重试，但距上次尝试至少 30 秒，正常成功轮次仍保持一分钟。时钟回拨不会永久冻结任务，换时区重新从当地昨天起查。每轮有两分钟执行上限，暂停立即取消正在进行的网络请求；分块与未知回执留待下一轮对账。

自动上传可以在后台继续。页面读取和内容回调仍要求前台与原账号，不能因为后台上传获准而把旧页面内容显示出来。Android 挂起或终止进程会延迟执行，不承诺强制绕过系统后台策略；待真机验证恢复行为及调度延迟。

最近成功时间来自资料存储回执。来源读取失败、队列未清空或仅上传了分块均不更新成功时间。自动错误与本机资料读取错误分开，仍保留手动重试入口。

## 已确认历史占用

发送队列只对以下旧版本收缩完整发送副本：该版本有校验通过的服务器回执，同一资料另有更新版本的有效回执，而且没有保留中的修复依赖它的正文。最新版本、未确认版本、需要对账的版本均不收缩。

保留旧 event ID、修订号、载荷哈希、续签/修复别名及服务器回执。崩溃后旧日志重放只匹配这些证据，不重新发旧 POST；同版本不同内容仍拒绝。随后才收缩来源日志中的对应发送快照，保留初始版本归属。两个文件之间崩溃可恢复。

当前载荷合计上限 16 MiB，原子状态文件上限 32 MiB，历史回执最多 16,384 条。超限明确停止，不静默清除最新资料。默认其他业务的 `AtomicDocument` 上限仍是 8 MiB。队列 schema 4、来源日志 schema 2；旧 dev72 不兼容，安装前必须完成可用回退方案。

## 尚未收口

断网期间正文继续增长、旧发送仍未确认时，现有逻辑会停在 `LIFELOG_PENDING_REVISION_CHANGED`。不能为取得版本号而把旧正文补发，也不能仅凭一次 404 假定旧请求永远不会到达。下一批补服务器原子确认/撤销旧发送，再以最新正文继续。当前分支未把这一场景报告为通过，自动同步尚未发布。

现有合成证据覆盖：12 次超长资料修订与跨文件崩溃重放；前后台切换、关闭同步、账号改变、重启调度、退避、网络恢复、日期补查与时区变化。发布/真机/正式资料验证另行记录。
